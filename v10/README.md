# V10 P1-1 · 项目与资源持久化基础

本提交从 P1-0 技术验证分支继续，新增 `v10/` 模块。V9 入口和既有导出协议保持原样。

- `domain.ts` 按 V1.5 定义项目、场景、资源和动画类型。项目文档持有唯一的素材集合，按 ID 的查询与 Clip 反向索引由 selector 派生。
- `project.ts` 检查版本台账、身份、主要领域引用以及包内资源路径。旧 ID 和扩展字段随文档原样存储。新项目从 revision 1 开始。
- `project-store.ts` 使用同一 IndexedDB 事务提交 Project、资源版本和 staging lease。暂存时计算 SHA-256，保存时检查实体、资源及 Project 预期版本，读取时验证活动资源的长度和摘要。删除推进 tombstone 水位；过期 staging 可按 24 小时清理。
- `mask.ts` 使用 SSM1 位图协议。12 字节头包含四字节 ASCII 魔数和两个小端 UInt32 尺寸字段，其后每像素一个不透明度字节，逐行存储。新增裁切区域填 255，从原图坐标重叠区复制旧像素。原始 PNG Alpha 独立保存。

## 验证

TypeScript 严格检查通过。在 Edge 中运行真实 IndexedDB browser 测试，覆盖创建、关闭连接后重开、PNG 与 Mask 读取、裁切蒙版映射、损坏引用、错误尺寸回滚后以同一版本重新提交、两个独立连接争用、三种冲突分类、删除水位和暂存清理。

复现时可用 P1-0 原型的锁文件环境。以 `tests/project-store.browser.ts` 作为 esbuild 浏览器 bundle 入口，将 bundle 内联至带 `<pre id="result">` 的 HTML。浏览器打开后查看 JSON，也可用 P1-0 的 `spike/browser.mjs` 读取结果。

## 剩余边界

当前模块还未接入编辑器或项目包导入导出。V9 迁移实现、跨标签页 UI、正式应用刷新恢复、Command / History、撤销重做时的 tombstone 恢复以及无引用资源回收仍待接入。当前存储拒绝普通 Create 重用 tombstone ID。SSM1 是本轮实现的 bitmap 线格式，RLE 仍待协议和解码支持。已知几何的 Mask 映射已可测试，未知几何的用户选择由后续命令和编辑器接入。

## P1-2 交互基础与浏览器回归

`coordinates.ts` 集中处理视口、DPR、旋转/缩放与命中，以及 Source Trim、Clip 校准和 Atlas Trim 的转换。绘制与命中共用矩阵。命中测试跳过隐藏、锁定及透明像素对象，Z 值相同使用绘制顺序，控制柄半径以 CSS 像素计。

`interaction.ts` 是主指针与手势草稿的唯一拥有者，只发布手势类型和是否交互。成功释放指针时产生一个命令请求，取消、失焦、丢失 capture 与卸载均清理草稿。`workspace-lifecycle.ts` 在工作区切换、换工具、导入和自动识别时取消手势及旧异步任务。

`reactive-store.ts` 将项目、UI、交互摘要和播放状态分别发布。组件使用只读视图和 selector。未变化的子对象保留引用，临时 UI 变化无需推进项目版本。

使用 Node 24，在 P1-0 spike 目录执行一次 `npm ci`，设置 `V10_BROWSER` 为 Chromium 或 Edge 路径，然后从仓库根目录执行 `node v10/tests/run-browser.mjs`。可用 `V10_SPIKE_PACKAGE` 指向另一个装好依赖的 P1-0 package.json，用 `V10_BROWSER_ARTIFACTS` 把临时配置指到工作目录。运行器使用本机回环地址和全新浏览器配置。已在 Edge 验证原生 pointer capture、取消、订阅分区、两个真实标签页争用以及刷新回读。

当前阶段提供运行时与自动化测试页面。生产工作区、各工具的具体 draft 命令以及多点闭合多边形仍需在编辑器接入时完成。

## P1-3 首批命令

`command-bus.ts` 开始接管素材基础属性更新。创建命令时从单一快照捕获实体和 Project 版本。多素材编辑提交一个事务，验证失败时整体拒绝。仅当绝对属性赋值的目标版本完全不变时，对无关 Project CAS 冲突重试一次。实体和资源冲突不重试。持久化成功后才向 Store 发布。已验证中文属性批量更新、无关提交后的安全重试、旧目标版本冲突、重复 dispatch 和空操作。

当前命令入口仅支持名称、分类、说明和旧版分组标签。事务撤销重做、CompositeCommand、几何与资源命令仍属 P1-3 后续工作。

### 审查修订

待执行命令仅保存项目 ID、属性补丁和版本预期，最多保留 128 条，调用方可显式取消草稿。提交结果将持久化与发布错误分开，订阅者异常报告不阻断其他订阅者。

失败结果的 baseRevision 来自准备时，attemptedRevision 来自最后一次实际提交，未进入持久化时为 null。attempts 统计实际提交次数。retryable 表示调用方可以刷新并重新准备新命令，现有命令 ID 已消费。遇到第二次 Project CAS 冲突时，明确返回冲突，由调用方决定是否重新准备。目标实体和资源冲突需要先检查变更。

首次读取比准备时更新，只要目标预期未变，仍可进行首次实际提交。仅实际提交遇到 Project CAS 冲突才消耗重试机会，最多提交两次。若持久化已成功但发布报错，调用方应从持久化层重新载入项目来恢复视图。

### 属性历史

CommandBus 对已成功提交的素材属性批次维护会话内撤销和重做。每笔历史操作使用原事务的目标并执行新的 Project CAS，版本继续递增。外部写入后拒绝跨历史断点恢复，无自动 rebase。撤销可移除本来不存在的可选属性；批量编辑整体恢复。历史在当前会话中最多 100 项并按 30 天修剪，此段描述初始会话版，当前持久化行为见下方。

### 组合属性命令

`prepareCompositeSpriteProperties` 按顺序验证子操作并合成绝对属性变更。同一字段由最后一个子操作赋值，所有变更在一个事务提交，各受影响素材的 revision 只推进一次。撤销重做处理整个批次；没有实际改变的素材不进入历史。当前历史与项目共同提交；界面发布异常仍通过 publishError 单独报告。

Edge 已验证无效子操作拒绝整批、双素材组合一次提交、双素材一次撤销或重做以及无变化子操作。异构组合（几何、PNG、蒙版等）和持久化历史仍待实现。

### 替换现有 PNG 和蒙版

`prepareSpriteRasterReplacement` 支持一次替换素材独占的现有 PNG 和/或现有位图蒙版。保持像素尺寸不变，稳定资源 ID 随新字节递增 revision，并在同一事务更新引用、素材 contentVersion 和 Project revision。资源操作不自动 rebase。会话内撤销重做以原字节提交新版本，并尊重外部写入冲突。历史按 30 天、100 项和每项目 1 GiB 的会话预算修剪。

更改几何尺寸、初次添加或移除蒙版、共享资源拆分与持久化历史仍待后续接入。

### 裁切几何与蒙版

`prepareSpriteCrop` 接收已生成的新 PNG 与源图裁切矩形。原素材必须有已知源图矩形，且与当前 PNG 尺寸一致。多边形点按新旧原点平移，蒙版按源图重叠区域映射，新增像素填 255。资源、几何与版本整体提交，撤销重做恢复精确的旧矩形、点和字节。场景中的现有摆放数据保持其独立编辑语义。

### 添加与移除位图蒙版

素材无蒙版时可用 `prepareSpriteMaskAttachment` 新建独立资源。有蒙版时可用 `prepareSpriteMaskRemoval` 移除独占引用并写入资源 tombstone。撤销与重做保留稳定资源 ID 并继续推进水位。历史恢复使用显式 tombstone 预期，存储事务只接受与最后一个活动蒙版版本 hash、长度都相同的暂存字节。普通新增仍拒绝复用 tombstone ID。当前历史重开规则见下方。

### 历史持久化

IndexedDB v2 增加按项目和 timeline ID 存储的 history 表。正式命令、撤销和重做在同一 Project CAS 事务提交项目、资源及历史快照，失败时不推进历史和项目。v1 项目原样打开，历史从空开始。

构建 CommandBus 时保留其 historyId，再以相同 ID 创建新实例即可在重开后续用撤销和重做。默认新实例获得新 ID，避免一个标签页撤销另一个标签页的历史。界面接入时要为当前编辑会话保存该 ID。当前历史快照直接保留资源字节，单条 timeline 依 30 天、100 项、1 GiB 修剪。每个项目的所有 timeline 共同受 30 天、100 项和 1 GiB 的历史预算约束。精简会截断历史链，避免撤销或重做跨过已丢弃的命令。

`collectRetiredResources(projectId)` 在单个写事务中清理项目内过期历史和已退休资源。现用版本不回收；历史仍需恢复已移除蒙版时，保留其 tombstone 之前最后一个版本。退休版本至少保留 24 小时。旧库未知退休时间的记录首次发现时开始计时。项目、素材和资源 revision 水位不因回收改变。此 API 已验证，正式编辑器还需决定触发回收的时机。

Edge 已验证数据库关闭后重开、蒙版历史恢复、不同 timeline 隔离、项目 CAS 失败时历史不变、以及 v1 → v2 数据保留。

### 素材创建和删除

`prepareSpriteCreation` 原子写入新 Sprite 和 PNG，`prepareSpriteDeletion` 移除未被场景、组或动画引用且独立持有资源的素材。删除不级联移除依赖。撤销恢复原有顺序、Sprite ID、PNG 和蒙版 ID，并按 tombstone 继续推进版本。恢复使用最后一个活动版本的字节摘要，退休资源回收会保护仍被历史引用的 PNG 和蒙版。

### 场景项更新与顺序

`prepareSceneItemUpdates` 原子更新现有场景项的层级、位置、变换和显示属性。`prepareSceneOrder` 接收完整的底到顶顺序并以一条历史命令更新 zIndex。锁定项移动会拒绝整个批次。只更新受影响场景项版本，场景集合成员版本保持不变。新增场景项入口将随编辑器接入。

### Agent 标注导入

`prepareAgentAnnotationImport` 使用 V10 Sprite ID 接收结构化标签、置信度、复核状态和扩展元数据。整个批次共享一笔事务和一条撤销记录。无效值或未知目标拒绝整批，资源、几何与像素版本保持原值。V9 v1/v2 JSON 的 ID 映射和适配仍属 P1-4A。

## P1-4A V9 ZIP 读取

`readV9Archive` 在浏览器内读取实际 V9 场景 ZIP，验证中央目录、文件名、解压长度、CRC、包内路径和 Manifest 标识。支持 STORE 和 DEFLATE，拒绝卷组、加密、ZIP64 和越界档案。压缩与展开的包级上限各 512 MiB，单条目 128 MiB，最多 8192 项。

Edge 用仓库内 A-010 实际导出包验证了 30 张 PNG、中文文件名和所有源裁切尺寸；另验了 DEFLATE、损坏 CRC、截断包和路径穿越拒绝。ZIP 读取后可生成迁移预览，见下文。

### V9 迁移预览与保存

`previewV9Migration` 先扫描旧 ID、文件路径和 PNG，建立完整 UUID 映射，再转换场景摆放和关系。缺失、尺寸不符与重复 ID 进入隔离报告。保留来源元数据、旧锚点、旋转角度和未知字段。原图缺失及 V9 未存盘蒙版均在报告提示。孤立 PNG 需要显式选择才纳入导入。

`saveV9Migration` 接收用户确认后的预览，在一笔事务创建新的 V10 项目和全部资源。实际 A-010 整包 30 项已迁移，重开后 UUID 和资源保持一致。另验了重复 ID 全组隔离、非零平移/旋转/缩放、无法解析的关系和资源不匹配时不创建半个项目。浏览器正式入口和 V9 Agent 结果协议仍待接入。

### V9 兼容导出

`exportV9Scene` 重新生成冻结的 `spatial-scene-layout/v2` Manifest、中文路径和 ZIP。关系输出旧序号，独立 idMap 提供当前序号与 V10 UUID 的映射。没有蒙版的 PNG 保持原字节；有编辑蒙版时导出有效 Alpha，Manifest 保持 V9 结构。无原图尺寸或素材未完成场景布局时拒绝导出，避免生成不兼容项目。

Edge 用实际 A-010 验证了迁移、重开和重新导出。30 张 PNG 哈希与原包相同，Manifest 字段和值一致。另验证了添加蒙版后 PNG 的 Alpha 生效且 Manifest 不变。

### V9 Agent 结果预览

`previewV9AgentAnnotations` 识别既有 v1/v2 结果，先核对已知源图尺寸，再把唯一的旧素材 ID 和关系映射至当前 V10 UUID。重复目标、歧义 ID 与缺失关系报告给调用方。批量确认可应用标签、置信度和复核状态，名称、布局及其他提案保留供复核，现有场景不被自动替换。

A-009 真实结果的 30 个目标均通过 UUID 映射、批量写入及撤销。另验证了 v1 字段别名、重复目标拒绝和未映射关系提示。

## P1-4A 浏览器兼容工作台

独立入口位于 `v10/workbench`。生成单文件 HTML 后可用 Edge 直接打开。支持选择 V9 ZIP、检查迁移提示、预览素材、保存至浏览器本地存储、刷新后重开以及下载 V9 兼容 ZIP。V9 正式入口保持原样。此版本聚焦兼容工作流，尚未连入完整切分、精修和动画界面。

使用 Node 24，先在 P1-0 spike 目录安装锁定依赖，然后执行 `node v10/workbench/build.mjs <输出 HTML 路径>`。如果依赖安装在另一个 spike 副本，设置 `V10_SPIKE_PACKAGE` 为那个 package.json 的绝对路径。浏览器自动化已在独立 Edge 配置下通过 file:// 实际上传 A-010、保存、刷新重开、素材 UUID 一致及 ZIP 下载。

V9 导出保留有效的原 legacy ID、序号和文件名。只有新素材或缺失/歧义序号需要分配，关系随最终导出 ID 序列化。回归已覆盖素材重排、序号有缺口和新素材加入。

人工验收已确认 A-010 显示的素材共 30 项，并成功下载 `A-008_scene_layers_rgb-v9.zip`。素材面板标题增加显式计数，Edge 自动化覆盖空态、预览和重开。

### 编辑与 Agent 标注接线

保存后的项目可在素材检查器修改名称、分类和描述，在场景表单更新坐标、顺序、显示和锁定。所有修改走命令总线；撤销和重做使用当前标签页的历史 ID，刷新并重新打开项目后可继续。发生写入冲突时可重新读取当前项目。

V9 Agent JSON 使用显式预览和确认。界面显示可应用目标数及提示，应用后可查看所选素材的标签，整批可撤销。Edge 已用 A-010 和 A-009 在 file:// 验证改名、移动、刷新后撤销重做、30 项 Agent 导入及兼容下载。

### 源图自动切分

兼容工作台可导入 PNG、JPEG、WebP，使用 V9 的 Alpha 或浅色背景识别、相邻像素规则和裁切边距。匹配结果可预览并保存为 V10 项目，项目保留原图与裁切 PNG。已保存项目可以按新的参数重新识别并另存。原图上限为 64 MiB 和 16 Mi 像素。

对透明 Alpha、4/8 邻域、检测阈值、边缘浅色和封闭高光用例，自动测试直接对照仓库中的 V9 实现验证裁切范围、组件顺序和二值蒙版。Edge file:// 验证源图导入、计数、保存后重开、素材 UUID 及重新识别。

保存源图项目后，可以在原图上拖出矩形，或用像素坐标直接调整选中素材的裁切范围。显式保存后更新裁切图，保留新旧矩形重叠区域的现有像素。Edge 验证了真实鼠标拖框、非法坐标拦截、Alpha 保留及撤销重做。

### Agent 任务包往返

保存了原图与素材范围的项目可以导出任务包，包含 source.png、候选清单和提示词。任务包用持久 UUID 关联素材，在结果提供项目 ID 或源图哈希时检查一致性。旧 V9 结果仍可按旧 ID 导入。部分标注保留已有字段，未采纳的名称和摆放提案继续作为元数据保留。

Edge 覆盖任务包下载、清单与裁切坐标、来源不匹配拦截及标注回导。迁移时缺失原图的项目可导入既有标注，任务包导出需先具备原图。

### 手工新增素材

保存原图项目后，可把矩形选区新增为素材，即使自动识别结果为零也可以继续。素材 PNG、UUID 和场景摆放在同一个事务创建，撤销时一起移除，重做恢复相同 UUID。Edge 覆盖从零素材开始、撤销、重做和导出。
