# V7 精灵图切分编辑器｜Agent 使用说明

版本：V7\
用途：供视觉 Agent / 多模态 Agent
读取，完成候选精灵的语义识别、命名、分类与标注，并将结果回写到编辑器。\
适用文件：`精灵图切分编辑器_V7_独立精修与画布操作增强版.html`

## 1. Agent 的职责边界

Agent 负责： - 根据原图和候选选区识别实际元素； -
为每个候选选区生成简洁、准确的中文名称； - 给出适合文件名的英文
`slug`； - 选择分类，补充描述和 tags； -
给出识别置信度，并标记需要人工复核的对象。

Agent 不负责： - 修改、推测或重排任何候选选区的坐标； -
修改候选选区宽高、像素蒙版或轮廓； - 擅自合并、拆分或删除候选选区； -
把未确定的语义当成事实。无法识别时应降低 confidence 并标记
`needs_review`。

**重要：V7 当前提供的是文件式自动化接口，不是 HTTP
API，也不是可直接远程调用的 REST 服务。**\
编辑器通过"导出 Agent 任务包"输出输入文件，再通过"导入 Agent 标注"读取
Agent 返回的 JSON。Agent 可以由人工调用，也可以由外部自动化流程读取
ZIP、调用视觉模型、生成 JSON，再交回编辑器。

## 2. 标准工作流

1.  人类在 V7 中导入原始场景图。
2.  执行自动识别，或手动追加矩形 / 多边形选区。
3.  人类先检查候选框，必要时进行重叠清理和单独精修。
4.  点击 **导出 Agent 任务包**。
5.  编辑器下载一个 ZIP，包含：
    -   `source.png`：完整原始图像；
    -   `agent_task.json`：任务元数据、候选选区及 Agent 指令；
    -   `AGENT_PROMPT.txt`：纯文本任务说明。
6.  Agent 读取 ZIP，逐个识别候选元素。
7.  Agent 生成 `agent_result.json`，顶层 schema 必须是
    `sprite-agent-result/v1`。
8.  人类回到编辑器，点击 **导入 Agent 标注**，选择 `agent_result.json`。
9.  编辑器按 `sprite_id` 将名称、分类、描述和 tags 写回对应候选选区。
10. 人类抽查结果，必要时修改属性，再导出最终素材。

## 3. 输入接口：agent_task.json

当前任务包的 JSON 结构如下（字段值为示例）：

``` json
{
  "schema": "sprite-agent-task/v1",
  "instructions": "识别每个候选选区对应的实际图像元素……",
  "source": {
    "filename": "deep_sea_scene",
    "width": 2048,
    "height": 1024
  },
  "sprites": [
    {
      "sprite_id": "sprite_001",
      "name": "sprite_001",
      "bbox": {
        "x": 120,
        "y": 80,
        "width": 160,
        "height": 210
      },
      "category": "",
      "description": "",
      "mask_available": true
    }
  ]
}
```

### 字段说明

  -------------------------------------------------------------------------------------
  字段                    含义                       Agent 使用规则
  ----------------------- -------------------------- ----------------------------------
  `schema`                输入协议版本               必须识别为 `sprite-agent-task/v1`

  `instructions`          编辑器内置任务说明         应遵循其中的输出约束

  `source.filename`       原图文件名（不含扩展名）   仅作来源标识

  `source.width` /        原图像素尺寸               用于理解 bbox 坐标空间
  `height`                                           

  `sprites[]`             候选选区列表               每项对应一个待识别素材

  `sprite_id`             稳定于本次任务的候选 ID    原样返回，不得重排或改写

  `bbox`                  原图坐标系中的矩形边界     用于在 `source.png`
                                                     中定位候选内容；不可修改

  `category`              当前已有分类               可在结果中补全或修正

  `description`           当前已有描述               可补充

  `mask_available`        是否存在像素蒙版           只作参考，不代表蒙版轮廓已提供给
                                                     Agent
  -------------------------------------------------------------------------------------

### 坐标规则

-   原点为原图左上角 `(0,0)`。
-   `x` 向右增加，`y` 向下增加。
-   `bbox.width`、`bbox.height` 是像素宽高。
-   bbox 仅用于视觉定位；最终裁切仍由编辑器中的原选区 / 蒙版决定。
-   当前任务包只提供原图和 bbox
    元数据，不会为每个候选自动生成独立裁切图或完整像素蒙版。Agent 应按
    bbox 在 `source.png` 中查看对应区域，并结合适量上下文识别。

## 4. 输出接口：agent_result.json

顶层结构必须符合：

``` json
{
  "schema": "sprite-agent-result/v1",
  "sprites": [
    {
      "sprite_id": "sprite_001",
      "name": "蓝色发光水母",
      "slug": "blue_glowing_jellyfish",
      "category": "creature",
      "description": "漂浮在场景中的蓝色发光水母，具有半透明触须。",
      "tags": ["水母", "发光", "蓝色", "深海"],
      "confidence": 0.96,
      "review_status": "ok"
    }
  ]
}
```

### 输出字段

  ------------------------------------------------------------------------------------------
  字段              类型              是否建议          说明
  ----------------- ----------------- ----------------- ------------------------------------
  `schema`          string            必须              固定为 `sprite-agent-result/v1`

  `sprites`         array             必须              标注结果列表

  `sprite_id`       string            必须              必须原样对应输入 ID

  `name`            string            建议              中文可读名称，简洁且可区分

  `slug`            string            建议              英文小写 snake_case 文件名建议；当前
                                                        V7 导入器不写入该字段

  `category`        string            建议              使用下方推荐分类

  `description`     string            建议              描述可见形态、颜色、用途或识别依据

  `tags`            string\[\]        建议              3--8 个简洁关键词为宜

  `confidence`      number            建议              0 到 1 的置信度

  `review_status`   string            建议              `ok` 或 `needs_review`
  ------------------------------------------------------------------------------------------

**导入器实际写入字段：**
`name`、`category`、`description`、`tags`、`confidence`、`review_status`。\
`slug` 虽可由 Agent 输出，但当前 V7 导入逻辑不会保存它；如需文件名
slug，请在后续素材流水线中单独保留。

## 5. 推荐分类体系

优先使用以下英文分类值：

  分类             适用内容
  ---------------- -----------------------------------
  `character`      人物、主角、NPC
  `creature`       鱼类、水母、怪物、动物等生物
  `prop`           可独立使用的道具、物件
  `architecture`   建筑、房屋、遗迹、设施
  `background`     背景层、远景装饰、天空 / 海底背景
  `terrain`        地形、岩石、岛屿、地表结构
  `vegetation`     海草、珊瑚、植物
  `effect`         光效、粒子、气泡、能量效果
  `UI`             界面图标、按钮、面板元素
  `other`          无法归入以上分类的内容

分类要表达素材的主要用途，不要只按颜色或外形分类。一个元素若同时具备多个属性，主分类选最主要用途，其余写入
tags。

## 6. 识别与标注准则

-   以 `bbox`
    指定区域为主要识别范围；可以查看边缘外少量上下文，但不要把相邻物体误认为当前选区的一部分。
-   若框内有多个对象，判断它们是否构成一个有意义的整体；不要擅自拆成多个
    ID。
-   若候选只包含物体的一部分，描述应如实反映局部，不要臆造完整对象。
-   对抽象光效、阴影、装饰碎片等难以命名内容，可使用"蓝色环形光效""岩石碎片"等描述性名称。
-   无法可靠判断时，使用中性名称，例如"未识别装饰元素 01"，并设置
    `review_status: "needs_review"`。
-   不要将透明背景、选区边界或重叠框线当成图像元素。
-   名称应避免重复；若多个元素同类，可加入方位、颜色、形态或编号区分。

## 7. ID 对应与导入限制（非常重要）

V7 当前导入逻辑会从 `sprite_id`
中提取数字，并将其映射到候选列表的序号： - `sprite_001` → 当前列表第 1
个候选； - `sprite_002` → 当前列表第 2 个候选； - 依此类推。

因此： 1. Agent 必须原样返回 `sprite_id`。 2. 不得对候选列表排序后再生成
ID。 3. 不得新增输入中不存在的 ID。 4. 不得把某个候选的标注写到另一个
ID。 5. 建议每个输入候选都返回一条结果；如无法判断，也返回
`needs_review`。 6.
导入前不要在人类侧重新执行自动识别、删除或重排候选，否则列表序号可能变化。若候选已变化，应重新导出任务包并重新标注。

当前导入器会忽略无法映射到现有列表的 ID。它不会导入 bbox、mask
或几何编辑结果。

## 8. 自动化流程建议

可将文件接口串成如下流水线：

``` text
V7 导出 Agent 任务 ZIP
        ↓
自动化程序解压 ZIP
        ↓
读取 agent_task.json + source.png
        ↓
逐个 bbox 裁切 / 视觉识别 / 命名分类
        ↓
校验 sprite_id 完整性与唯一性
        ↓
生成 agent_result.json
        ↓
人工检查 JSON
        ↓
V7 导入 Agent 标注
        ↓
最终人工复核与导出
```

### 导入前校验清单

-   [ ] JSON 可正常解析。
-   [ ] `schema` 精确等于 `sprite-agent-result/v1`。
-   [ ] `sprites` 是数组。
-   [ ] 每条记录都包含有效的 `sprite_id`。
-   [ ] `sprite_id` 与任务包中的 ID 一一对应。
-   [ ] `confidence` 为 0--1 数值。
-   [ ] `tags` 为字符串数组。
-   [ ] 没有坐标、宽高、mask 等未经授权的几何修改字段。

## 9. 当前接口能力与限制

当前可用： - 导出包含原图、任务 JSON、提示词的 ZIP； - 导入 Agent
JSON； - 回写名称、分类、描述、tags、confidence、review_status； - 由
Agent 负责语义识别，人类负责几何选区与最终确认。

当前尚未提供： - HTTP / REST API； - WebSocket 或实时双向 Agent 通信； -
编辑器内置模型调用； - Agent 直接操作画布、移动选区、修改 mask； -
每个候选的独立裁切图自动打包； - `slug` 的持久化写入； - 可靠的 UUID 级
ID（当前 ID 与候选列表序号关联）。

建议现阶段把它作为"人类切分 + Agent 批量识别标注 +
人类复核"的半自动工作流。后续若需要真正无人值守，可再增加稳定
UUID、逐个候选裁切图、批量 JSON 校验和本地 HTTP / CLI 桥接层。
