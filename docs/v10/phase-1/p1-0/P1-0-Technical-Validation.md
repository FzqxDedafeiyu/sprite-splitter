## 交付和持久化判断

IndexedDB 可作为事务层原型的候选。正式验证需要把 Revision 和资源引用连同二进制内容纳入同一提交条件，并验证重开、重复执行和跨标签页冲突。单 HTML 已证明能携带离线 Worker 和存储原型。是否能携带完整 OpenCV/WASM，以及静态多文件包能否满足双击打开，需要用实际产物比较。


## 后续验证与决策

- 工程构建通过。两份独立工作目录均完成类型检查、5 项测试和 Vite 构建。第二份使用锁文件和本地依赖缓存执行 `npm ci --offline`。两次 JS 产物 SHA-256 一致，为 `665f19a9e76f65b73ea928b22b0d7ae3e94b8ce95e1d06e6e625f99be93ac2ed`。使用了 Codex 自带的 Node 运行构建，本机另一套 Node 在写入时触发 EPERM。
- Canvas 浏览器验证通过。在 Edge 中以 160 × 120 CSS 像素显示 320 × 240 的画布，构造带平移的变换并把模拟指针逆变换回 (6, 7)。画布编码和解码为 PNG 后采样得到 RGBA [255, 0, 0, 255]。
- A-010 往返通过。从 V9 抽取原始 ZIP writer，重打包后全部 31 个条目逐字节相同。截断与 CRC 损坏均被原型读取器拒绝。重打包产物另用 Python 完整解压并验证中文名、PNG 尺寸和 RGBA。
- 固定版 OpenCV 4.12.0 实测通过。下载的原文件为 10,872,775 字节，SHA-256 为 `c7d6967284acc7eb50897eeb4186690444396bbe834aeb7caf7a565285976829`。将它内联到单 HTML 的 Blob Worker，独立 Edge 配置屏蔽外部域名后仍能通过 `file://` 初始化并运行真实 GrabCut。合成图中心与边缘分别得到 1、0。收到批次开始消息后终止 Worker，观察窗口内未收到完成消息。初始化需兼容 OpenCV 自身的 Emscripten thenable；直接 await 该对象导致超时，等待回调并避免返回对象本身后通过。

**交付建议。** 继续验证单 HTML 路线，OpenCV 的内联可行性已有证据。固定测试的 OpenCV 文件约 10.9 MB，原型使用 Base64 后体积还会增加。正式发布前需量测启动耗时、内存、跨浏览器表现，并比较离线多文件包。IndexedDB 可用于后续持久化验证，跨标签页冲突、刷新后回读、过期 Worker 结果防护以及正式浏览器 ZIP 导入入口仍需完成。

**阶段边界。** 当前已完成本轮 P1-0 技术证据归档。产品实现尚未开始。后续工作以冻结规格和实际步骤验收为准。
