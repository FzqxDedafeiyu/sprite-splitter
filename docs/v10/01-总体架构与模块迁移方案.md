# V10 总体架构与模块迁移方案

> 文档版本：V1.5
> 文档状态：冻结设计基线（Frozen Implementation Baseline）
> 适用基线：精灵图切分编辑器 V9
> 修订日期：2026-11-26
> 目标：指导 Agent 将 V9 单文件工具渐进演进为 V10 精灵图生产工作台。
> 原则：先稳定数据与交互，再扩展动画工作区；保留已验证的图像处理算法。

## 0. V1.5 修订记录

本版在 V1.4 基础上完成四项冻结补充：Source Trim 与 Atlas Trim 的坐标术语分离；二进制资源 revision / contentHash、CAS、临时资源 GC 与 History 保留契约；实体 / 资源 / Project Revision 矩阵；三类冲突及 Rebase / retry 流程。场景定位模型仍以 Sprite 左上角 position 为唯一绘制定位基准。

V1.5 冻结决策：
1. sourceTrimOrigin / Rᵢ 只表示当前 Sprite PNG 原点在 sourceLocal 中的位置；atlasTrimOffset 只表示 Atlas Pack 裁切矩形原点在 Sprite Local 中的位置。两者属于不同层级，不得互换或继续使用无上下文的 trimOffset。
2. Mask、SourceImage 与 Sprite PNG 使用独立 ResourceVersion；资源以稳定 resourceId 标识，revision 单调递增，contentHash 使用 SHA-256。Atlas 导出资源为不可变产物，以 contentHash 标识。
3. RevisionLedger 为已删除实体 / 资源保留版本水位，支持 Create / undo / redo 后版本不回退；每次成功业务事务均递增 Project revision。
4. Command expected 值必须来自创建命令时的同一 Store / Project 快照；Create 使用 absent expectation；undo / redo 使用上一次成功提交后的 revision 与 hash。
5. 冲突分为 target-entity、resource、project-cas。仅在目标读写集与资源均未变化、且命令不依赖全局集合不变量时，Project CAS 冲突允许刷新后自动 rebase 并重试一次；实体或资源冲突必须重新计算，必要时由用户二次确认。
6. 临时资源失败即清理；崩溃遗留资源按 24 小时宽限期 GC。History 引用的旧资源在 History 项有效期内不得回收；默认保留 30 天、最多 100 项、最多 1 GiB 历史资源，先达到任一上限即淘汰最旧项。

V1.4 核心决策：
1. Mask 资源以当前 Sprite 像素内容的 spriteLocal 为坐标基准，尺寸必须与当前 Sprite PNG 一致；Trim / 裁切变化必须通过原子命令同步转换 Mask，不得静默丢弃或沿用旧尺寸。
2. 动画涉及的 Source Local、Sprite Local 与 Clip Canvas 坐标转换统一由 Animation System 规格定义；本文件只定义跨模块术语与资源边界。
3. Project 持久化采用项目 revision compare-and-swap；Command 同时校验受影响实体 / 资源 revision。冲突拒绝提交，不采用 last-write-wins。

V1.3 核心决策：
1. V9 场景渲染的定位基准是 Sprite 左上角：V9 `scenePosition = (sceneX ?? x, sceneY ?? y)`；V10 使用 `SceneLayout.position` 表示该世界坐标，Scene Anchor 不得替代绘制原点。
2. V9 `anchor` 是 source-image 全局坐标的参考标记，只用于标注，不参与 V9 Sprite 绘制定位；迁移后保留为独立 `sceneAnchor`；V9 Manifest 无法区分显式值与导出默认值，统一标记 legacy-unknown。
3. V9 `transform.x/y` 是相对 sourceRect 左上角的平移量；V10 场景左上角位置为 `sourceRect.origin + transform.translation`。缩放和旋转继续围绕 Sprite 中心应用，不改变位置字段的含义。
4. ProjectDocument 正式增加 SourceImage、可选持久化 Mask、AgentAnnotation、SceneGroup 与 SceneWorld 元数据。
5. V9 ZIP 没有原始整图字节；只有来源尺寸元数据时，必须建立 missing 状态的 SourceImage，不能伪造可用原图。
6. Mask 分为原始 PNG Alpha、用户可编辑 Mask、最终导出 Alpha；V9 未导出的内存 Mask 不可迁移，但 V10 新产生的 Mask 必须可保存重开。
7. 缺失 / 歧义映射使用判别联合，不得以空字符串 UUID 或全零 sourceRect 伪造有效数据。
8. 重复 legacyId 的记录整体隔离，不得参与实体合并、布局写入或引用解析。
9. V9 场景 Manifest 不定义动画帧序列；不得把 sceneAnchor 当作 Animation Pivot，也不得凭素材相似或相邻顺序自动推断动画组。
10. PNG 实际像素尺寸必须与已知 sourceRect 尺寸一致；不一致时阻断该 Sprite 自动导入并记录 error。

V1.2 中错误或含混的“sceneAnchor = legacyAnchor + transform.translation”不再承担场景绘制定位职责；该值只作为参考锚点迁移。场景绘制位置以独立 position 为唯一基准。

## 1. 产品目标与范围

V10 从「精灵图切割编辑器」升级为本地优先的 2D 游戏素材生产工具，形成：
1. 图片导入与识别。
2. 自动 / 手工精灵图切割。
3. 元素管理与属性编辑。
4. 精修。
5. 场景布局与视差检视。
6. 动画校准与预览。
7. 质量检查和资源导出。

V10 必须同时满足：
- 保留 V9 已有且稳定的 Alpha 识别、背景抠除、矩形 / 多边形选区、GrabCut、分组属性、场景布局、视差检视、Agent JSON、PNG / JSON / ZIP 导出能力。
- 修复交互模式冲突、鼠标误触、指针取消后状态残留、数据更新后界面不同步、撤销覆盖不完整等架构性问题。
- 支持角色和物体两类动作组，组级与单帧级双向校准。
- 角色枢轴按动作类型推荐，地面动作默认脚底中心，并允许切换骨盆、身体根节点、动作点等。
- 自动校准同时提供非破坏性预览和自动应用两种模式。
- 动画导出支持 PNG 序列 + JSON Manifest，以及 Sprite Sheet。
- 核心编辑流程可离线使用；GrabCut / 智能收边在当前实现方案下需联网加载 OpenCV.js，除非后续完成本地打包验证。

## 2. 非目标与约束

### 2.1 本轮不做的事
- 不为了模块化而重写图像分割、抠图、GrabCut 等算法。
- 不把场景锚点、动画枢轴、帧偏移合并成一个字段。
- 不将 Agent 建议直接写入用户数据。
- 不把某一个游戏引擎的数据格式作为内部唯一数据模型。
- 不在架构迁移阶段同时进行大规模视觉改版。
- 不以数组下标作为长期资源身份。

### 2.2 兼容性约束
- V10 兼容层必须识别 V9 实际产生的导出物，而不是假设存在 V9 完整项目文件。
- 旧字段保留在迁移层解释；无法映射的字段放入 legacyExtensions 并给出报告。
- V9 导出物中没有持久化的 mask 不属于可迁移数据，必须提示重新切割或精修。
- 任何批量修改、自动校准、Agent 导入均须可整体撤销。
- V10 项目数据应可保存、关闭、重新打开并保持一致。

## 3. 当前 V9 架构基线与主要风险

V9 主体是单文件 HTML，界面、样式、业务算法、状态与事件处理集中在一个文件中。核心状态包含图片、sprites 数组、selected、zoom、addMode、lassoMode、refineMode、drag、history 等。

静态源码审查已识别的风险（运行时仍需测试确认）：
1. 交互模式由多个独立布尔值控制，非互斥，Canvas pointerdown 依赖 if 顺序决定优先级。
2. 自动识别等操作没有统一清理交互状态，可能残留套索或精修模式。
3. 指针生命周期未完整覆盖 pointercancel / lostpointercapture / window blur。
4. 多处直接修改 sprites 后手动调用 draw、refreshList、syncInspectorProperties 等，容易漏刷新。
5. Sprite 对象混合裁切几何、场景属性、动画相关潜在语义和 UI 状态。
6. 元素标识与数组索引耦合，排序或删除可能破坏外部引用。
7. 撤销快照覆盖不完整，部分删除、属性、Agent 导入、场景操作未形成统一历史事务。
8. 场景旋转绘制与命中检测坐标计算可能不一致。
9. 视差检视更新可能重复重建列表 DOM，拖动时存在性能风险。
10. 部分重叠清理逻辑可能使用与自动分割不同的像素归属结果。

以上问题应转化为回归测试，不应只依赖人工体验判断是否修复。

## 4. 目标架构

采用分层、模块化、单一数据源架构：

```text
Application Shell
├── Workspace Layer
│   ├── Import / Detection Workspace
│   ├── Sprite Editing Workspace
│   ├── Inspector / Refinement Workspace
│   ├── Scene Layout Workspace
│   └── Animation Workspace
├── Application Services
│   ├── Interaction Manager
│   ├── Command Bus / History Manager
│   ├── Calibration Engine
│   ├── Quality Inspector
│   ├── Export Manager
│   └── Agent Adapter
├── Domain Layer
│   ├── Project
│   ├── Sprite Asset
│   ├── Scene Layout
│   ├── Animation Set / Clip / Frame
│   └── Pivot Presets
├── State Layer
│   ├── Reactive Store
│   ├── Selectors
│   └── Persistence
└── Infrastructure
    ├── Existing Image Algorithms
    ├── Canvas Renderer
    ├── File Import / Export
    └── Optional AI / Engine Adapters
```

### 4.1 模块职责与边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| Sprite System | Sprite 身份、裁切几何、像素数据、分类与元数据 | 场景摆放、动画帧播放 |
| Scene Layout | 场景坐标、层级、视差、Scene Anchor | Animation Pivot |
| Animation System | 动作组、Clip、Frame、Pivot、Offset、FPS、PlaybackState | 修改原始裁切几何 |
| Interaction Manager | 真实交互状态、指针捕获、取消、Gesture Draft | 业务数据持久化 |
| Reactive Store | Project 数据、UI 状态、只读交互快照、订阅与派生选择器 | 真实 pointerId / 活跃指针会话 |
| Command / History | 统一数据修改、事务、撤销重做 | UI 组件状态 |
| Calibration Engine | 枢轴候选、帧对齐、偏移计算 | 未经确认直接覆盖用户数据 |
| Quality Inspector | 规则检查与问题定位 | 自动修复所有警告 |
| Export Manager | 场景与动画导出协议 | 内部动画数据定义 |
| Agent Adapter | 外部建议校验、预览、应用 | 绕过 Command 直接改 Store |

模块之间通过明确接口通信，禁止跨模块直接修改对方内部对象。

## 5. 技术栈与构建策略

建议目标采用 TypeScript + Vite 模块化工程，拆分领域模型、交互逻辑、渲染器和工作区。

源码工程与用户交付形态是两个独立决策：
- 源码工程：建议 TypeScript + Vite。
- 交付形态：保留本地使用，可评估构建为单文件 HTML，或提供包含本地资源的离线 ZIP。
- 不得在尚未验证文件读取、Worker、字体、资源 URL 和浏览器兼容性前，承诺单文件构建必然无损。

实施前设置技术验证门：
1. 现有算法能否在模块化工程中复用。
2. 文件导入、下载、ZIP、Canvas、Worker 的构建后行为。
3. 核心编辑流程断网时资源是否全部可用。
4. OpenCV.js 本地打包对产物体积、启动时间和单文件构建的影响。
5. 构建产物是否可直接打开，或是否需要本地静态服务器。
6. 是否能继续保留 Agent JSON 工作流。

在验证结果出来前，不把单文件 HTML 或多文件工程写死为唯一交付方式。

## 6. 领域数据模型总览

Project 是持久化根对象，至少包含：
- projectSchemaVersion: 10
- projectId
- assets（唯一权威 Sprite 集合；sprites 仅为派生视图）
- sceneLayout
- animationSets
- pivotPresets
- projectSettings
- migrationMetadata
- legacyExtensions

SpriteAsset 使用稳定 UUID，负责原始裁切素材和内容元数据，至少包含 contentVersion。像素来源、Alpha / mask 或裁切几何发生会影响缓存结果的变化时，必须递增 contentVersion。Scene Layout 和 Animation Frame 通过 spriteId 引用 Sprite，不复制其身份。

legacyAnchor 作为旧版锚点的兼容信息，归属于对应 Sprite 的迁移扩展数据（或等价的 Sprite-level legacyExtensions 条目），不作为 Animation Pivot 使用；成功映射为 sceneAnchor 后仍保留来源记录，直至兼容迁移确认完成。


### 6.1 核心领域模型（权威 Schema）

以下接口是 V10 内部持久化模型的规范基线。字段可在后续版本扩展，但不得在不同模块各自定义同名字段的不同语义。

```ts
type UUID = string;
type SpriteLayer = "background" | "midground" | "foreground";
type SpriteShape = "rectangle" | "polygon";

interface Point {
  x: number;
  y: number;
}

interface Rect {
  x: number;
  y: number;
  width: number;
  height: number;
}

interface ResourceVersion {
  resourceId: UUID;                  // 逻辑资源身份；替换字节时保持不变
  revision: number;                  // 从 1 开始单调递增；资源字节变化时递增
  contentHash: string;               // sha256:<64 lowercase hex>，对完整资源字节计算
  byteLength: number;                // 实际资源字节数
}

interface SourceImage {
  id: UUID;
  revision: number;
  filename: string;
  width: number;
  height: number;
  availability: "available" | "missing";
  assetRef?: string;                 // 仅 available 时存在；相对项目包根目录
  resourceVersion?: ResourceVersion; // available 时必须存在；与原图字节对应
  legacyExtensions?: Record<string, unknown>;
}

interface RasterRef extends ResourceVersion {
  kind: "mask";
  assetRef: string;                  // 项目包内资源路径，相对项目包根目录
  coordinateSpace: "spriteLocal";  // 当前 Sprite PNG 左上角为 (0,0)
  width: number;                     // 必须等于对应 Sprite PNG 的实际宽度
  height: number;                    // 必须等于对应 Sprite PNG 的实际高度
  encoding: "bitmap" | "rle";      // 字节布局由带版本的编码协议定义
}

interface AgentAnnotation {
  tags: string[];
  confidence?: number;               // 仅来源明确提供时写入，范围 0..1
  reviewStatus?: string;             // 保留来源原值，不擅自归一未知枚举
  sourceAgent?: string;
  updatedAt?: string;
  legacyExtensions?: Record<string, unknown>;
}

interface SpriteAsset {
  id: UUID;                         // V10 稳定 UUID，唯一身份
  legacyId?: string;                // 例如 V9 sprite_001，仅用于兼容追溯
  legacyIndex?: number;              // V9 1-based index，仅供显示 / 诊断
  name: string;
  category: string;
  description?: string;
  groupName?: string | null;          // 旧版素材分组元数据，不等同于 SceneGroup
  sourceImageId?: UUID;              // 关联原始整图；缺失原图时仍可保留来源元数据
  assetRef: string;                  // 裁切 Sprite PNG，相对项目包根目录
  rasterResource: ResourceVersion;   // Sprite PNG 的逻辑资源版本；assetRef 指向该版本字节
  sourceRect?: Rect;                 // source-image 像素坐标；未知时省略
  sourceRectStatus: "known" | "unknown";
  shape: SpriteShape;
  points?: Point[];                  // spriteLocal；rectangle 可省略
  mask?: RasterRef;                  // 用户可编辑 Mask；原始 PNG Alpha 不存入此字段
  agentAnnotation?: AgentAnnotation;
  contentVersion: number;            // 像素 / Alpha / mask / 几何缓存版本
  revision: number;                  // 本实体业务数据版本
  legacyAnchor?: Point;              // 原样保留的 V9 source-image 全局坐标
  legacyExtensions?: Record<string, unknown>;
}

interface SceneTransform {
  scaleX: number;
  scaleY: number;
  rotation: number;                  // 角度单位固定为 degree；围绕 Sprite 中心
}

interface SpriteRelations {
  nearTo: UUID[];
  attachedTo: UUID[];
  supports: UUID[];
}

interface SceneLayout {
  spriteId: UUID;                    // 与 SpriteAsset.id 对应
  layer: SpriteLayer;
  depth: number;
  parallax: number;
  zIndex: number;
  visible: boolean;
  locked: boolean;
  position: Point;                   // Sprite 未缩放、未旋转时的左上角 sceneWorld 坐标；唯一绘制定位基准
  transform: SceneTransform;         // 仅 scale / rotation；围绕 Sprite 中心
  sceneAnchor: Point;                // sceneWorld 参考标记，不决定绘制原点
  anchorSource: "explicit" | "defaulted" | "legacy-unknown";
  relations: SpriteRelations;        // 所有引用均为 V10 UUID
  revision: number;
}

interface SceneWorld {
  coordinateOrigin: "top-left";
  units: "source-pixels";
  width?: number;
  height?: number;
}

interface SceneLayoutDocument {
  revision: number;                  // world / mode / items 成员关系变化时递增
  mode?: string;                     // V9 layoutMode 等兼容语义
  world: SceneWorld;
  items: Record<UUID, SceneLayout>;  // key 必须等于 item.spriteId
}

interface SceneGroup {
  id: UUID;
  name: string;
  memberSpriteIds: UUID[];
  revision: number;
}

interface ProjectSettings {
  revision: number;
  colorSpace: "srgb";
  pixelArt: {
    enabled: boolean;
    renderSnap: "round" | "floor" | "none";
  };
  defaultFps: number;                 // 新项目默认 12 FPS
  autosaveEnabled: boolean;
  extensions?: Record<string, unknown>;
}

type LegacyIdMapping =
  | { status: "mapped"; legacyId: string; spriteId: UUID; legacyIndex?: number; sourceFile?: string }
  | { status: "missing_asset"; legacyId: string; legacyIndex?: number; sourceFile?: string }
  | { status: "ambiguous"; legacyId: string; legacyIndex?: number; sourceFile?: string; candidateFiles?: string[] };

interface MigrationMetadata {
  sourceFormat: string[];
  sourceProjectVersion?: number;
  migratedAt: string;
  adapterVersion: string;
  idMap: LegacyIdMapping[];
  warnings: MigrationWarning[];
}

interface MigrationWarning {
  code: string;
  severity: "info" | "warning" | "error";
  legacyId?: string;
  path?: string;
  message: string;
  resolution?: string;
}

interface RevisionLedger {
  entities: Record<string, number>; // entityType:id -> 最新版本；删除后保留 tombstone 水位
  resources: Record<string, number>; // resourceId -> 最新版本；资源字节 GC 后仍保留 ID 水位
}

interface ProjectDocument {
  kind: "sprite-project";
  projectSchemaVersion: 10;
  projectId: UUID;
  sourceImages: SourceImage[];
  assets: SpriteAsset[];             // 唯一权威 Sprite 集合
  sceneGroups: SceneGroup[];
  sceneLayout: SceneLayoutDocument;
  animationSets: AnimationSet[];
  animationClips: AnimationClip[];
  pivotPresets: PivotPreset[];
  projectSettings: ProjectSettings;
  migrationMetadata?: MigrationMetadata;
  legacyExtensions?: Record<string, unknown>;
  revision: number;                  // 项目级单调递增版本
  revisionLedger: RevisionLedger;     // live revision 与 ledger 对应；已删除 ID 不得复用
}
```

规范与约束：
- `assets` 是唯一权威 Sprite 集合；任何 `sprites` 数组只能由 selector 从 `assets` 派生，禁止同时持久化两份可变集合。
- `sceneLayout.items` 必须为每个已布局 Sprite 提供至多一个条目；条目 key、`spriteId` 和对应 SpriteAsset.id 必须一致。未参与场景布局的 Sprite 可以没有条目。
- 各持久化实体 revision 的完整递增条件、Create / undo / redo 规则见本文件 6.4 Revision Matrix；所有 revision 单调递增，恢复旧业务值也不得回退 revision。
- revisionLedger.entities 与 revisionLedger.resources 是版本水位权威记录；实体 / 资源被删除时仍保留 tombstone 水位，UUID / resourceId 永不复用。Ledger 与业务数据在同一 Project CAS 事务中提交。
- 项目从 V9 / 早期 V10 导入且没有 RevisionLedger 时，迁移器必须为所有活动实体和资源建立初始水位（revision 缺失时初始化为 1），同时将 ProjectDocument.revision 初始化为 1；不得凭空生成已删除对象的 tombstone。
- ProjectDocument.revision 在每个成功的持久化业务事务后恰好递增 1；失败、冲突、纯 UI 更新、临时资源写入不递增。
- 持久化写入必须以读取到的 ProjectDocument.revision 为 expectedProjectRevision 执行 compare-and-swap。项目 revision 不匹配时拒绝写入并报告冲突；同时校验本 Command 读取 / 修改的实体与资源 revision。不得以最后写入者覆盖并发更新。
- `contentVersion` 仅在像素内容、Alpha / mask 或裁切几何变化并影响派生缓存时递增；名称、分类、场景变换和 UI 操作不递增。
- `SourceImage` 保存原始整图元数据与可选原图字节引用。V9 ZIP 不含原图字节时，availability 必须为 missing，assetRef / resourceVersion 省略；用户补选并确认匹配后才可改为 available。SourceImage 元数据变化递增 SourceImage.revision；原图字节变化另递增 ResourceVersion.revision 并更新 contentHash。
- `SpriteAsset.assetRef` 与 `SourceImage.assetRef` 均相对项目包根目录，使用规范化 POSIX 相对路径；拒绝绝对路径、盘符路径、反斜杠路径穿越与规范化后重复路径。Sprite PNG 字节由 rasterResource 版本戳校验；路径相同不代表资源版本相同。
- `sourceRect` 使用原始输入图像像素坐标；未知时省略并设置 sourceRectStatus=unknown，不得用全零矩形表示未知。已知 sourceRect 的宽高必须与对应裁切 PNG 的实际像素尺寸完全一致。
- `points` 使用 spriteLocal 像素坐标。V9 导出前的多边形 points 是相对 Sprite 左上角的局部坐标，迁移时直通；rotation 是 degree，原样保留。
- `groupName` 仅承接 V9 素材分组字符串；若未来需要场景层级分组，使用独立 SceneGroup，不把场景成员关系塞入 SpriteAsset。
- 原始 PNG Alpha 是 Sprite PNG 的像素内容；`mask` 仅保存用户可编辑 Mask，坐标基准为当前 Sprite PNG 的 spriteLocal，尺寸必须与 Sprite PNG 完全一致。导出 Alpha 由原始 Alpha 与 Mask 逐像素相乘得到，未设置 Mask 时等于原始 Alpha。Mask 修改必须递增 contentVersion 与 SpriteAsset.revision。
- Mask 资源编码 `bitmap` / `rle` 仅声明资源表示类型；本版本不冻结 RLE 的起始 bit、扫描顺序、counts 语义、字节序或压缩率。具体编码必须由带版本的资源协议定义，并校验解码像素总数严格等于 width × height；不满足时资源无效并阻断导出 / 保存。Mask 的 resourceId / revision / contentHash / byteLength 必须与实际字节一致。
- Trim / 裁切或 Sprite 像素画布尺寸变化时，必须通过同一事务更新 Sprite PNG、sourceRect / Trim 元数据与 Mask 资源。Mask 按 sourceLocal 重叠区域映射到新 spriteLocal；新增区域填充 255（不额外抑制原始 Alpha），被裁掉区域同步移除。sourceRect / Trim 来源未知而无法建立可靠映射时，必须阻断自动转换并要求用户明确选择保留、重建或放弃 Mask；禁止静默置 null。
- UpdateSpriteMask 与改变 Sprite 像素尺寸 / Trim 的命令必须原子提交像素资源、Mask 资源引用、contentVersion、实体 revision 和 Project revision。失败或冲突时不得留下孤立的半成品资源引用。
- `AgentAnnotation` 保留来源实际提供的 tags / confidence / reviewStatus；未知 reviewStatus 原样保留，缺失 confidence 不得补造默认值。
- `SceneLayout.position` 是未缩放、未旋转 Sprite 左上角在 sceneWorld 的位置，也是场景渲染的唯一定位基准。Scene Anchor 只作参考标记，不得用于推导绘制原点。
- `SceneTransform` 只包含 scaleX / scaleY / rotation；rotation 单位为 degree，缩放和旋转围绕 Sprite 中心。V9 平移已折算进 position。
- `sceneAnchor` 使用 sceneWorld；V9 legacyAnchor 原样保留其 source-image 全局坐标。V9 兼容迁移时仅叠加旧平移量以保留标记的平移关系，不应用 scale / rotation；其来源由 anchorSource 区分 explicit / defaulted / legacy-unknown；V9 导出 Manifest 通常只能确定为 legacy-unknown。
- `SceneLayoutDocument.world` 保存 V9 source/canvas 的坐标原点、单位和尺寸；layoutMode 映射到 mode。
- V9 layer 枚举映射为 background / midground / foreground。缺失值才使用默认值：background depth=0.85、midground depth=0.5、foreground depth=0.15；parallax 默认分别为 0.35 / 0.70 / 1.00。已有数值必须原样保留。
- `relations` 的每个数组元素必须先经 legacy ID 映射转换成 UUID；目标缺失时不得留下悬空 UUID，应记录 unresolved relation warning 并把原始关系保存在扩展数据中。
- `legacyExtensions` 用于保留 V10 尚未建模的旧字段和来源数据，不得用它替代本节已定义的正式字段。

### 6.2 Project Settings 与 Migration Metadata

`projectSettings` 保存项目级用户偏好和默认值，不存放当前选中项、面板开合、播放时钟等临时 UI 状态。未知设置放入 `extensions`，不得静默删除。

`migrationMetadata` 是迁移审计信息，不是业务身份的替代品。其 `idMap` 必须完整记录每个 V9 sprite id 到 V10 UUID 的映射；生成 UUID 后先完成全量映射，再转换 relations、Agent 结果和其他外键。映射状态为 missing_asset / ambiguous 的记录不得被当作成功迁移。

### 6.4 Revision Matrix（冻结契约）

所有 Revision 均为非负整数，创建时从 1 开始；已存在实体 / 资源的每次成功业务修改递增 1。revision 只在成功事务提交时更新，不在 draft、预览、失败命令或临时资源写入时更新。

| 对象 | Revision 字段 / 水位 | 递增条件 | 不递增条件 |
|---|---|---|---|
| ProjectDocument | revision | 任一持久化业务事务成功提交，恰好 +1 | UI、播放时钟、Gesture draft、预览、失败 / 冲突 |
| SourceImage | revision | 文件名、尺寸、availability、来源元数据或资源引用关系变化 | 原图字节单独变化但元数据未变；该变化递增资源 revision |
| SpriteAsset | revision | 任一持久化字段变化 | 纯 UI / 派生缓存 |
| SpriteAsset.contentVersion | contentVersion | Sprite PNG 像素、Alpha、Mask、sourceRect / Trim 几何变化并影响像素派生缓存 | 名称、分类、描述、场景属性 |
| SceneLayoutDocument | revision | world、mode、items 成员增删 / 重绑定 | 单个 item 属性变化 |
| SceneLayout item | revision | 单个 Sprite 的图层、位置、变换、锚点、关系等变化 | 其他 item 变化 |
| SceneGroup | revision | 名称、成员关系变化 | 无关 Group 变化 |
| ProjectSettings | revision | 持久化设置变化 | UI 临时状态 |
| AnimationSet | revision | 名称、assetType、spriteIds 成员变化 | 单个 Clip 内部字段变化 |
| AnimationClip | revision | Clip 自身设置、canvas、pivotTarget、Clip 帧成员 / 顺序变化 | 单个 Frame 内部 Pivot / Offset 修改 |
| AnimationFrame | revision | spriteId、duration、alignment、metadata 任一字段变化 | 同 Clip 的其他 Frame 变化 |
| PivotPreset | revision | 预设名称、策略、参数、适用动作变化 | 仅被某帧引用，不改变预设本身 |
| MigrationMetadata | 无独立 revision | 仅随迁移 / 修复事务变化；由 Project revision 保护 | 常规业务编辑 |

资源版本与实体版本独立：

| 资源 | 版本契约 |
|---|---|
| SourceImage 原图、Sprite PNG、Mask Raster | 稳定 resourceId；新资源 revision=1；同一 resourceId 的字节发生变化时 revision +1，并重新计算 SHA-256 contentHash；字节未变不递增 |
| Atlas 导出图像 | 不可变导出产物，不使用可变 revision；每次构建生成 contentHash、byteLength 与新输出路径，校验内容完整性 |
| History 引用的旧资源字节 | 在引用它的 History 项有效期间保持可读，不得被覆盖或 GC |

**Command expected 值的唯一来源：** 用户操作开始并创建 Command 时，读取同一个不可变 Project / Store 快照。expectedProjectRevision 来自该快照的 ProjectDocument.revision；expectedEntityRevisions 来自该快照中 Command read-set / write-set 的实体 revision；expectedResourceRevisions 来自该快照解析到的 resourceId、revision 与 contentHash。禁止在 Command 创建后再从“最新 Store”拼接一部分 expected 值。

**Create / Delete / undo / redo：**
1. Create 为新 UUID / resourceId 声明 absent expectation；父集合 / 外键依赖仍须携带其当前 entity revision。成功创建后 entity / resource revision=1，并写入 RevisionLedger。
2. Update 使用 present expectation（revision 与适用时的 contentHash）。成功后对应实体 / 资源 revision +1；Project revision 同一事务 +1。
3. Delete 必须校验被删实体与关联资源版本；成功后实体 / 资源从活动集合移除，但 RevisionLedger 保留递增后的 tombstone 水位，ID 永不复用。
4. undo / redo 是新的业务事务，不恢复旧 revision。History 保存 before / after 快照与资源哈希；undo / redo 以当前 after revision / hash 为 expected，成功后再次递增 RevisionLedger。Create 的 undo 形成 tombstone，redo 使用同一逻辑 ID 并从 tombstone 水位继续递增。
5. 资源 undo / redo 可重新指向 History 保留的旧 contentHash 字节，但同一 resourceId 的 revision 仍递增；不得把旧 revision 数字写回。
6. contentVersion 与 entity/resource revision 各自独立；undo / redo 恢复旧像素内容时，contentVersion 仍按一次新的像素内容变更递增。

**资源暂存、提交与 GC：**
- 新资源先写入事务专属 staging 区，完成尺寸 / 编码 / SHA-256 校验后，再执行资源版本与 Project CAS。资源字节按 contentHash 不可变存储；Project Manifest 只在 CAS 成功时切换到新 ResourceVersion。
- CAS 失败时不发布新资源引用；本次 staging 资源立即标记为可清理。崩溃遗留 staging 项在重启扫描中超过 24 小时且无活跃事务租约时清理。
- 已提交资源若不再被 Project、有效 History、活跃任务 / 导出任务引用，进入 24 小时 GC 宽限期；宽限期结束再次检查引用后才删除。
- History 默认保留最近 30 天、最多 100 个命令、最多 1 GiB 的 History 专属二进制资源，任一上限先达到即淘汰最旧项；新命令提交后被清空的 redo 项立即释放引用。被淘汰项引用的资源在 24 小时 GC 宽限期后才可删除。以上参数可配置，但必须保留“先释放 History 引用、再延迟 GC”的顺序。
### 6.3 坐标空间术语表


| 术语 | 定义 |
|---|---|
| sourceLocal | 原始 SourceImage 像素坐标，左上角为 (0,0)；跨素材引用时必须同时标明 sourceImageId |
| sourceRect | sourceLocal 中的裁切矩形 |
| spriteLocal | 当前 Sprite PNG 局部像素坐标，左上角为 (0,0)；Mask 与 AnimationFrame.pivotLocal 使用此空间 |
| sourceTrimOrigin / Rᵢ | 当前 Sprite PNG 左上角在 SourceImage 的 sourceLocal 中的位置；属于 Sprite 来源裁切层，由 sourceRect.origin 派生，不重复存储。sourceLocal → spriteLocal：Pᵢ = Qᵢ − sourceTrimOriginᵢ |
| clipCanvas | Animation Clip 规范画布坐标，左上角为 (0,0) |
| atlasTrimOffset | Atlas Pack 裁切矩形左上角在完整 Sprite PNG 的 spriteLocal 中的位置；属于 Atlas 导出层，不参与 sourceLocal → spriteLocal 转换 |
| trimOffset | 禁止作为 V10 内部规范字段；旧格式别名仅能由适配器在明确知道所属层级时转换 |
| sceneWorld | 场景布局世界坐标 |
| viewport | 编辑器屏幕视口坐标，包含视口缩放和平移 |
| sceneAnchor | sceneWorld 中的场景参考标记，不决定 Sprite 绘制原点 |
| animationPivot | 只服务动画帧对齐的枢轴 |

禁止在跨模块接口中使用含义不明的泛化 canvas / world 字段名。若字段指动画画布，必须写 clipCanvas；若指编辑器视口，必须写 viewport。

Scene Anchor 与 Animation Pivot 是不同领域概念，不共享字段。详细动画坐标定义见《02-Animation-System-技术规格》。

## 7. 状态与修改原则

1. Reactive Store 是 Project 数据与 UI 可观察状态的权威来源。
2. Interaction Manager 是真实运行时 Gesture / Pointer Session 的唯一所有者。
3. Store 中的 InteractionSnapshot 仅为只读、可观察的 UI 快照（例如 gestureType、isInteracting；activeTool 唯一存储于 UIState.activeToolByWorkspace）；不得包含可被 UI 用来驱动真实指针会话的 pointerId、活跃 stroke buffer 或可变 draft。
4. UI 组件不持有第二份可独立修改的业务数据副本。
5. 业务数据只能通过 Command 修改。
6. 所有进入 History 的 Command 必须实现 undo；不可撤销的内部维护动作不得作为普通项目数据 Command 进入 History。
7. 批量操作使用 CompositeCommand / TransactionCommand，作为单一原子历史项。
8. 连续拖动在 pointerup 时提交为一个事务；pointercancel 时丢弃 draft 并回滚到开始前状态。
9. 派生数据通过 selector 计算，避免重复保存可推导字段。
10. Canvas 与面板从同一状态快照渲染。

### 7.1 动画播放与交互状态

PlaybackState 是 Animation System 的独立状态维度：Stopped、Playing、Paused；它不是 InteractionState 的一种 Gesture。Interaction Manager 同一时刻仍只允许一个主指针 Gesture。

当播放过程中开始拖动 Pivot 或 Frame Offset：
- 默认在 Gesture 开始时自动暂停播放，并记录暂停前状态。
- pointerup 提交校准后，默认恢复此前 Playing 状态；若用户设置为“操作后保持暂停”，则保持 Paused。
- pointercancel / lostpointercapture / blur 时先安全取消 Gesture，再按同一恢复策略处理播放状态。
- 切换 Clip、工作区或页面失焦时按 Animation System 规则清理播放时钟。
- PlaybackState 不进入 InteractionSnapshot 的互斥状态机，也不写入项目文件。

## 8. 渐进迁移路线

### Phase 0：基线固化
- 保存 V9 原始版本与可回退副本。

- 记录当前算法输出与关键交互行为。
- 为已知问题建立可复现步骤。

交付：V9 Baseline、测试素材包、已知问题清单。

### Phase 1：领域模型与兼容层
- 定义 Project、SpriteAsset、SceneLayout 类型。
- 为旧 Sprite 分配稳定 UUID。

- 保留旧 JSON 导入入口，但不得把 Agent 任务包误当作完整项目文件。
- 不改变切割算法行为。

验收：
- V9 实际导出 ZIP 和单独 Manifest 可识别，项目文件通过 kind + projectSchemaVersion 判别。

- V9 导出物未包含的 mask 不参与迁移；迁移报告明确提示重新切割或重新精修。
- UUID 在保存、重排、删除其他元素后保持稳定。

- 增加自动识别、切换工作区、导入等操作的交互清理策略。

验收：详见《03-Interaction-Manager与Reactive-Store技术规格》。

- 把高频 UI 更新与持久化数据更新分开。
- 建立 Command API，undo 为必填。

### Phase 4：Animation Domain

- 播放、暂停、逐帧、FPS、循环、洋葱皮。
- 使用 Interaction Manager 和 Command API，不建立私有交互体系。

### Phase 6：Calibration / QA / Export
- 几何候选与组级校准。

## 9. 项目文件、V9 迁移与版本协议

### 9.1 V10 项目文件

V10 项目文件根必须同时包含类型判别字段与 schema 版本：
```json
{
  "kind": "sprite-project",
  "projectSchemaVersion": 10
}
```
`kind` 用于在解析前识别文件类型；`projectSchemaVersion` 是项目持久化 schema 的整数版本。二者均不能用来判断动画、场景或 Agent 导出协议。缺少 kind、kind 不匹配或 schema 不受支持时，打开器应停止项目导入并给出明确错误，不得通过字段嗅探将其他 JSON 当作项目文件。

### 9.2 V9 可迁移输入范围
V9 没有完整项目保存文件。兼容层只承诺读取以下实际产物：
- 场景导出 ZIP：sprites/NNN_名称.png + manifest.json。
- 单独导出的场景 Manifest（format: spatial-scene-layout/v2）。
- 可选的 Agent 任务 / 结果 JSON：spatial-scene-agent-task/v2、spatial-scene-agent-result/v2，以及已明确支持的旧 sprite-agent-result/v1。

这些输入不等同于完整 V9 工程快照。V9 内存中的 mask 没有持久化格式，无法从上述导出物恢复。不得在迁移验收中承诺 mask 无损迁移。

### 9.3 V9 → V10 字段映射表

| V9 字段 | V10 目标字段 | 转换 / 保留规则 |
|---|---|---|
| `id`（如 sprite_001） | `SpriteAsset.id` + `legacyId` + `migrationMetadata.idMap` | 为无歧义记录生成 UUID；重复 ID 整组隔离，不生成可被引用的映射 |
| `index` | `legacyIndex` | 仅保留诊断序号，不作为身份 |
| `name` / `category` / `description` | 同名 SpriteAsset 字段 | 原样保留 |
| `group` | `SpriteAsset.groupName` | 保留旧素材分组字符串；不自动创建 SceneGroup |
| `visible` / `locked` | SceneLayout 同名字段 | 缺失时分别默认 true / false |
| `sourceRect{x,y,width,height}` | `SpriteAsset.sourceRect` | 原始输入图像像素；PNG 实际宽高必须与 rect 宽高一致 |
| `anchor{x,y}` | `SpriteAsset.legacyAnchor` + `SceneLayout.sceneAnchor` + `anchorSource` | 原样保留 source-image 全局坐标；按 9.4 保留平移后的参考标记，来源通常为 legacy-unknown，不决定绘制原点 |
| `layout.layer/depth/parallax/zIndex` | SceneLayout 同名字段 | 已存在值原样保留；缺失值按 V9 默认值或本节确定性规则补齐 |
| `transform{x,y,scaleX,scaleY,rotation}` | `SceneLayout.position` + `SceneLayout.transform` | x/y 折算为左上角 position；scale / rotation 进入 transform，rotation 为 degree |
| `relations.nearTo / attachedTo / supports` | `SceneLayout.relations` | 所有旧 ID 先通过完整 idMap 转为 UUID |
| `shape` / `points` | `SpriteAsset.shape / points` | V9 points 已是 spriteLocal，直通；rotation 为 degree，不重复换算 |
| `file` | `SpriteAsset.assetRef` | ZIP 内安全相对路径，相对项目包根目录 |
| V9 Agent 的 `tags / confidence / reviewStatus`（含 review_status） | `SpriteAsset.agentAnnotation` | 保留实际存在字段；缺失值不补造 |
| V9 顶层 `source` / `canvas` | `ProjectDocument.sourceImages` + `SceneLayoutDocument.world` | 保存尺寸与来源元数据；没有原图字节时 availability=missing |
| V9 顶层 `layoutMode` | `SceneLayoutDocument.mode` | 原样保留 |
| V10 新增精修 Mask | `SpriteAsset.mask` | V9 导出物不含 Mask；V10 Mask 必须持久化 |
| 未识别字段 | 对应实体或 Project 的 `legacyExtensions` | 保留原始键和值，并在迁移报告中列出 |



### 9.4 身份桥接、Anchor 换算与兼容边界

**Ordinal → UUID 桥接顺序：**
1. 读取所有有效 Manifest sprite 记录，收集 V9 `id`、`index` 和 `file`。
2. 为每个可导入素材生成 UUID，并一次性构建完整 `migrationMetadata.idMap`。
3. 再转换 relations、Agent 结果 JSON 及其他引用；禁止在映射表尚未完整时按数组位置临时推断。
4. Agent 结果中的 `sprite_id`、旧关系字段 `near_to` / `attached_to` 等别名只在 V9 Adapter 边界识别，进入 V10 领域模型前统一为 camelCase 与 UUID。
5. 无法解析的旧 ID 必须进入 warning / unresolved 列表，禁止按 index 猜测替代。

**V9 Scene Anchor 换算：**

**V9 实际渲染语义（已核对 V9 HTML 源码）：**

V9 的场景渲染取值为 `scenePos(s) = { x: s.sceneX ?? s.x, y: s.sceneY ?? s.y }`。绘制时先平移到 `scenePos + Sprite中心`，再旋转 / 缩放并以 `(-center)` 绘制裁切图。因此，`scenePos` 表示 Sprite 未缩放、未旋转时的左上角基准位置；Anchor 不参与绘制定位。V9 场景 Manifest 导出时：
```ts
transform.x = (sceneX ?? x) - x;
transform.y = (sceneY ?? y) - y;
scenePosition = sourceRect.origin + transform.translation;
```

V10 迁移必须拆分位置与变换：
```ts
position = {
  x: sourceRect.x + legacyTransform.x,
  y: sourceRect.y + legacyTransform.y
};
transform = {
  scaleX: legacyTransform.scaleX ?? 1,
  scaleY: legacyTransform.scaleY ?? 1,
  rotation: legacyTransform.rotation ?? 0
};
sceneAnchor = {
  x: legacyAnchor.x + legacyTransform.x,
  y: legacyAnchor.y + legacyTransform.y
};
```
其中 position 是场景渲染唯一定位基准；sceneAnchor 仅保留参考标记，不能被当作 Sprite 左上角。scale / rotation 围绕 Sprite 中心执行，不写回 position，也不重复应用于 legacyAnchor。

V9 导出器始终写入 `anchor` 字段，值为 `s.anchor || defaultAnchor(s)`；因此，仅凭 V9 导出的 Manifest 无法判断该值原本来自用户显式设置还是导出时生成的默认值。此类记录统一设置 `anchorSource: "legacy-unknown"`，不得伪称 explicit 或 defaulted。只有输入 Manifest 确实缺少 anchor、由 V10 迁移器自行按 `defaultAnchor(s) = { x: round(s.x + s.w/2), y: round(s.y + s.h) }` 补出时，才设置 defaulted；V10 用户明确设置的新值才标记 explicit。

迁移验收必须逐项比较 V9 与 V10 的 Sprite 左上角 sceneWorld 位置、变换后包围盒和实际绘制像素；至少覆盖非零平移、非 1 缩放、非零旋转。另行比较 Anchor 标记位置，但 Anchor 对齐不能替代绘制位置验收。

**V9 兼容协议冻结：**
- `spatial-scene-layout/v2` 的既有字段名、嵌套结构、枚举、序号语义和目录布局均视为冻结协议。
- V9 兼容导出不得为了遵循 V10 camelCase 而重命名旧字段；V10 camelCase 只约束内部模型和新协议。
- 兼容导出不得强制增加旧消费者不认识的字段。V10 UUID 与旧 ordinal 的关联通过独立 `sprite-id-map.json` 辅助文件提供；旧 Manifest 本体保持原样。
- 新动画 Manifest 的 Frame 记录可选携带 `legacySpriteId`，供旧场景 Manifest 与 V10 UUID 对照；没有 legacy ID 的新素材省略该字段。

### 9.5 Agent v1 / v2 适配协议

V9 Agent Adapter 至少识别已发布 V9 实际接受的任务 / 结果协议：
- `spatial-scene-agent-task/v2`
- `spatial-scene-agent-result/v2`
- `sprite-agent-result/v1`

V9 结果输入可能使用 `sprite_id`，关系别名可能使用 `near_to` / `attached_to`。这些旧命名仅在适配层接受；进入 V10 内部模型后统一为 `spriteId` 与 `relations.nearTo / attachedTo / supports`。不得把 V9 JSON 原样直接 cast 为 V10 类型。不同协议版本的字段差异必须由各自 adapter 显式校验；未识别字段保留到 legacyExtensions 并报告。适配器不得臆造缺失关系或素材身份。

### 9.6 迁移规则与异常输入处理

1. 迁移前保留原始导出物；迁移过程纯函数化，输出 ProjectDocument 与结构化 warnings。
2. UUID 在同一项目内唯一；生成并持久化后，后续保存 / 重开不得重新生成。
3. 先扫描全部 legacyId 并计算唯一性，再建立 idMap；只有唯一且资源有效的记录可进入 mapped 分支。
4. `LegacyIdMapping` 使用判别联合：mapped 必须有 spriteId；missing_asset / ambiguous 不得出现 spriteId。禁止空字符串 UUID。
5. 同一 legacyId 出现多条 Manifest 记录时，该 ID 的全部记录均标记 ambiguous；不得让任意一条成为“胜出记录”，不得写入 SpriteAsset、SceneLayout、relations 或 AgentAnnotation。原始记录全部进入迁移报告隔离区，等待用户手工消歧。
6. Manifest 引用的 PNG 缺失、不可解码或为 0 字节：跳过对应 Sprite，记录 error；所有引用它的 relations / Agent 标注转为 unresolved，不生成悬空 UUID。
7. 已知 sourceRect 的 PNG 实际像素宽高必须分别等于 sourceRect.width / height；不一致按 resource error 处理，阻断该 Sprite 自动导入，不得仅 warning 后继续进入动画计算。
8. ZIP 中存在未被 Manifest 引用的有效 PNG：可作为 orphan 素材导入，但 sourceRectStatus 必须为 unknown，sourceRect 省略；不得用 {0,0,0,0} 伪装已知裁切坐标。等待用户指定原图和区域。
9. V9 ZIP 不含原始整图字节。若 Manifest 有 source/canvas 元数据，建立 SourceImage 元数据记录，availability=missing 且不设置 assetRef；提示用户可补选原图。补选前项目仍可编辑现有 Sprite，但不可重新切割完整原图。
10. V9 内存中的 mask 未进入导出物，不属于可迁移数据；V10 新建或编辑的 Mask 必须以 RasterRef 持久化，并在保存关闭重开后保持一致。
11. V9 导出器会把默认 Anchor 一并写入 Manifest，无法从导出文件判断它是否由用户显式设置；这类记录一律标记 anchorSource=legacy-unknown。只有 Manifest 缺失 anchor、迁移器自行按 sourceRect 底边中心补值时标记 defaulted；V10 新编辑器中用户明确设置的值标记 explicit。数值非法时保留原始值到 legacyExtensions 并产生 warning。
12. 缺失 zIndex 时，按 Manifest 原始记录顺序生成稳定值（每条递增 10）；若有有效 index，先按 index 排序，index 重复或无效时退回 Manifest 顺序并警告。V9 实际导出通常已有 zIndex，默认值仅用于异常输入。
13. ProjectSettings.defaultFps 缺失时固定为 12。
14. assetRef / SourceImage.assetRef 均相对项目包根目录；路径规范化后仍须位于包内。拒绝绝对路径、盘符路径、`..` 路径穿越、反斜杠混淆与重复规范化路径。
15. 未知字段放入 legacyExtensions；顶层 source / canvas / layoutMode 必须映射到正式字段，不得仅塞进扩展区。
16. V9 points 已是 spriteLocal，rotation 是 degree；按原值迁移，不重复做 sourceRect 偏移或角度换算。
17. relations 与 Agent 引用必须在完整 idMap 建立后统一转换；无映射目标保留原始旧 ID 并产生 unresolved warning。
18. Manifest 缺失、JSON 无法解析、schema 不支持或 ZIP 损坏：阻断自动迁移并说明原因。
19. 迁移报告列出成功、跳过、警告、无法自动映射项目、缺失原图、不可恢复 Mask 和需要人工消歧的记录；用户确认后另存为 V10 项目，不覆盖原始文件。

### 9.7 导出协议并存
- V9 兼容场景导出保留冻结协议：format = spatial-scene-layout/v2，字段名、目录与序号语义不变。
- V10 动画导出使用独立 format = sprite-anim-manifest/v1，内部字段使用 camelCase。
- V10 项目文件使用 kind = sprite-project 与 projectSchemaVersion = 10。
- 两种导出在 UI 入口、文件命名和 Manifest 解析器中明确区分，不互相覆盖。
- `sprite-id-map.json` 在需要跨接 V9 场景与 V10 动画数据的导出包中提供 legacyId ↔ spriteId 映射，不修改冻结的 V9 Manifest。
- 项目版本、导出 format 与 Agent 协议版本互不替代。

## 11. Agent 实施约束

Agent 每个阶段必须：
1. 先阅读本目录三份规格和 V9 基线文件。
2. 明确本阶段允许修改的模块和禁止修改的算法。
3. 先给出实施计划和受影响文件清单。
4. 小步提交，不在一个任务中同时重写多个核心系统。
5. 为每个新增行为提供自动化测试或可复现手工验收步骤。
6. 不得为了通过测试而删除旧功能。
7. 每阶段结束提供变更摘要、测试结果、已知限制和回滚方式。
8. 未经明确授权，不得直接把实验性版本替换为正式 V9 文件。
9. 严格遵守三份规格的坐标术语、状态归属、命令事务与导出协议。

## 12. V10 阶段完成定义

V10 不是以「界面看起来完整」作为完成标准。至少满足：
- V9 实际导出物可迁移，且不可恢复数据明确告知。
- 原有图像算法回归通过。
- 交互状态不冲突，指针异常能恢复。
- Interaction Manager 独占真实 Gesture 会话。
- 多面板由统一 Store 同步。
- 数据修改有一致的撤销 / 重做和原子事务。
- 动画数据能保存和重开。
- 组级 / 单帧校准能互相配合。
- 自动校准不覆盖手工结果。
- 预览和导出位置一致。
- PNG 序列、JSON、Sprite Sheet 的坐标与 Trim 结果可验证。
- 核心编辑流程离线可用；联网依赖能力有明确标识。
