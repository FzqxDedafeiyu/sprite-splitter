# V10 总体架构与模块迁移方案

> 文档版本：V1.2
> 文档状态：修订设计基线（Implementation Blueprint）
> 适用基线：精灵图切分编辑器 V9
> 修订日期：2026-11-26
> 目标：指导 Agent 将 V9 单文件工具渐进演进为 V10 精灵图生产工作台。
> 原则：先稳定数据与交互，再扩展动画工作区；保留已验证的图像处理算法。

## 0. V1.2 修订记录

本版在 V1.1 架构决策上补全核心领域 Schema、V9→V10 字段映射、旧 ID 到 UUID 桥接、Scene Anchor 坐标换算、项目文件判别、导出关联键与迁移异常策略。V1.1 已关闭的坐标公式、交互状态归属、事务撤销和双协议并存决策保持不变。

V1.2 核心决策：
1. `ProjectDocument.assets` 是 SpriteAsset 的唯一权威集合；`sprites` 仅为 UI / selector 派生视图，不是第二份持久化数组。
2. `sceneLayout.items` 以 `spriteId` 为键保存每个 Sprite 的场景布局；场景属性不混入 SpriteAsset。
3. V10 项目根必须包含 `kind: "sprite-project"` 与 `projectSchemaVersion: 10`。
4. V9 旧 ID 在迁移时先建立完整 `legacyId → UUID` 映射，再转换 Agent 引用与场景关系。
5. V9 兼容场景导出字段冻结；V10 camelCase 规范只约束 V10 内部模型和新协议。
6. V9 Anchor 从 source-image 全局坐标迁移到 sceneWorld 时，按已核对的 V9 平移语义执行 `sceneAnchor = legacyAnchor + transform.translation`；缩放和旋转不得重复应用。
7. 对无法可靠判定的旧几何坐标或损坏资源必须产生迁移警告，不得猜测或静默丢弃。

本版根据两份独立 Agent 交叉审查报告修订，重点关闭坐标语义、交互状态归属、事务撤销、V9 迁移边界、版本字段、双导出协议和跨文档命名等实现歧义。

已确定的架构决策：
1. Interaction Manager 独占运行时指针会话和真实 Gesture 状态；Store 只暴露只读、可观察的 InteractionSnapshot。
2. 所有进入 History 的 Command 必须有 undo；批量操作使用 CompositeCommand / TransactionCommand 原子提交。
3. Animation PlaybackState 与 Interaction Gesture 是独立状态维度；开始校准拖拽时默认自动暂停，结束后按策略恢复。
4. V9 场景导出协议继续保留；V10 动画导出新增独立协议，不替换旧协议。
5. V10 项目文件版本使用 projectSchemaVersion；动画导出使用字符串 format，二者不混用。
6. V9 迁移源仅限实际存在的导出物；V9 未持久化的 mask 不承诺迁移。
7. 第一阶段离线保证核心编辑流程；GrabCut / 智能收边仍标注为需联网，是否本地打包 OpenCV.js 留待技术验证，不作离线承诺。

## 1. 产品目标与范围

V10 从「精灵图切割编辑器」升级为本地优先的 2D 游戏素材生产工具，形成：
1. 图片导入与识别。
2. 自动 / 手工精灵图切割。
3. 元素管理与属性编辑。
4. 精修。
5. 场景布局与视差检视。
6. 动画校准与预览。
7. 质量检查和资源导出。

V10 必须同时满足：
- 保留 V9 已有且稳定的 Alpha 识别、背景抠除、矩形 / 多边形选区、GrabCut、分组属性、场景布局、视差检视、Agent JSON、PNG / JSON / ZIP 导出能力。
- 修复交互模式冲突、鼠标误触、指针取消后状态残留、数据更新后界面不同步、撤销覆盖不完整等架构性问题。
- 支持角色和物体两类动作组，组级与单帧级双向校准。
- 角色枢轴按动作类型推荐，地面动作默认脚底中心，并允许切换骨盆、身体根节点、动作点等。
- 自动校准同时提供非破坏性预览和自动应用两种模式。
- 动画导出支持 PNG 序列 + JSON Manifest，以及 Sprite Sheet。
- 核心编辑流程可离线使用；GrabCut / 智能收边在当前实现方案下需联网加载 OpenCV.js，除非后续完成本地打包验证。

## 2. 非目标与约束

### 2.1 本轮不做的事
- 不为了模块化而重写图像分割、抠图、GrabCut 等算法。
- 不把场景锚点、动画枢轴、帧偏移合并成一个字段。
- 不将 Agent 建议直接写入用户数据。
- 不把某一个游戏引擎的数据格式作为内部唯一数据模型。
- 不在架构迁移阶段同时进行大规模视觉改版。
- 不以数组下标作为长期资源身份。

### 2.2 兼容性约束
- V10 兼容层必须识别 V9 实际产生的导出物，而不是假设存在 V9 完整项目文件。
- 旧字段保留在迁移层解释；无法映射的字段放入 legacyExtensions 并给出报告。
- V9 导出物中没有持久化的 mask 不属于可迁移数据，必须提示重新切割或精修。
- 任何批量修改、自动校准、Agent 导入均须可整体撤销。
- V10 项目数据应可保存、关闭、重新打开并保持一致。

## 3. 当前 V9 架构基线与主要风险

V9 主体是单文件 HTML，界面、样式、业务算法、状态与事件处理集中在一个文件中。核心状态包含图片、sprites 数组、selected、zoom、addMode、lassoMode、refineMode、drag、history 等。

静态源码审查已识别的风险（运行时仍需测试确认）：
1. 交互模式由多个独立布尔值控制，非互斥，Canvas pointerdown 依赖 if 顺序决定优先级。
2. 自动识别等操作没有统一清理交互状态，可能残留套索或精修模式。
3. 指针生命周期未完整覆盖 pointercancel / lostpointercapture / window blur。
4. 多处直接修改 sprites 后手动调用 draw、refreshList、syncInspectorProperties 等，容易漏刷新。
5. Sprite 对象混合裁切几何、场景属性、动画相关潜在语义和 UI 状态。
6. 元素标识与数组索引耦合，排序或删除可能破坏外部引用。
7. 撤销快照覆盖不完整，部分删除、属性、Agent 导入、场景操作未形成统一历史事务。
8. 场景旋转绘制与命中检测坐标计算可能不一致。
9. 视差检视更新可能重复重建列表 DOM，拖动时存在性能风险。
10. 部分重叠清理逻辑可能使用与自动分割不同的像素归属结果。

以上问题应转化为回归测试，不应只依赖人工体验判断是否修复。

## 4. 目标架构

采用分层、模块化、单一数据源架构：

```text
Application Shell
├── Workspace Layer
│   ├── Import / Detection Workspace
│   ├── Sprite Editing Workspace
│   ├── Inspector / Refinement Workspace
│   ├── Scene Layout Workspace
│   └── Animation Workspace
├── Application Services
│   ├── Interaction Manager
│   ├── Command Bus / History Manager
│   ├── Calibration Engine
│   ├── Quality Inspector
│   ├── Export Manager
│   └── Agent Adapter
├── Domain Layer
│   ├── Project
│   ├── Sprite Asset
│   ├── Scene Layout
│   ├── Animation Set / Clip / Frame
│   └── Pivot Presets
├── State Layer
│   ├── Reactive Store
│   ├── Selectors
│   └── Persistence
└── Infrastructure
    ├── Existing Image Algorithms
    ├── Canvas Renderer
    ├── File Import / Export
    └── Optional AI / Engine Adapters
```

### 4.1 模块职责与边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| Sprite System | Sprite 身份、裁切几何、像素数据、分类与元数据 | 场景摆放、动画帧播放 |
| Scene Layout | 场景坐标、层级、视差、Scene Anchor | Animation Pivot |
| Animation System | 动作组、Clip、Frame、Pivot、Offset、FPS、PlaybackState | 修改原始裁切几何 |
| Interaction Manager | 真实交互状态、指针捕获、取消、Gesture Draft | 业务数据持久化 |
| Reactive Store | Project 数据、UI 状态、只读交互快照、订阅与派生选择器 | 真实 pointerId / 活跃指针会话 |
| Command / History | 统一数据修改、事务、撤销重做 | UI 组件状态 |
| Calibration Engine | 枢轴候选、帧对齐、偏移计算 | 未经确认直接覆盖用户数据 |
| Quality Inspector | 规则检查与问题定位 | 自动修复所有警告 |
| Export Manager | 场景与动画导出协议 | 内部动画数据定义 |
| Agent Adapter | 外部建议校验、预览、应用 | 绕过 Command 直接改 Store |

模块之间通过明确接口通信，禁止跨模块直接修改对方内部对象。

## 5. 技术栈与构建策略

建议目标采用 TypeScript + Vite 模块化工程，拆分领域模型、交互逻辑、渲染器和工作区。

源码工程与用户交付形态是两个独立决策：
- 源码工程：建议 TypeScript + Vite。
- 交付形态：保留本地使用，可评估构建为单文件 HTML，或提供包含本地资源的离线 ZIP。
- 不得在尚未验证文件读取、Worker、字体、资源 URL 和浏览器兼容性前，承诺单文件构建必然无损。

实施前设置技术验证门：
1. 现有算法能否在模块化工程中复用。
2. 文件导入、下载、ZIP、Canvas、Worker 的构建后行为。
3. 核心编辑流程断网时资源是否全部可用。
4. OpenCV.js 本地打包对产物体积、启动时间和单文件构建的影响。
5. 构建产物是否可直接打开，或是否需要本地静态服务器。
6. 是否能继续保留 Agent JSON 工作流。

在验证结果出来前，不把单文件 HTML 或多文件工程写死为唯一交付方式。

## 6. 领域数据模型总览

Project 是持久化根对象，至少包含：
- projectSchemaVersion: 10
- projectId
- assets（唯一权威 Sprite 集合；sprites 仅为派生视图）
- sceneLayout
- animationSets
- pivotPresets
- projectSettings
- migrationMetadata
- legacyExtensions

SpriteAsset 使用稳定 UUID，负责原始裁切素材和内容元数据，至少包含 contentVersion。像素来源、Alpha / mask 或裁切几何发生会影响缓存结果的变化时，必须递增 contentVersion。Scene Layout 和 Animation Frame 通过 spriteId 引用 Sprite，不复制其身份。

legacyAnchor 作为旧版锚点的兼容信息，归属于对应 Sprite 的迁移扩展数据（或等价的 Sprite-level legacyExtensions 条目），不作为 Animation Pivot 使用；成功映射为 sceneAnchor 后仍保留来源记录，直至兼容迁移确认完成。


### 6.1 核心领域模型（权威 Schema）

以下接口是 V10 内部持久化模型的规范基线。字段可在后续版本扩展，但不得在不同模块各自定义同名字段的不同语义。

```ts
type UUID = string;
type SpriteLayer = "background" | "midground" | "foreground";
type SpriteShape = "rectangle" | "polygon";

interface Point {
  x: number;
  y: number;
}

interface Rect {
  x: number;
  y: number;
  width: number;
  height: number;
}

interface SpriteAsset {
  id: UUID;                         // V10 稳定 UUID，唯一身份
  legacyId?: string;                // 例如 V9 sprite_001，仅用于兼容追溯
  legacyIndex?: number;              // V9 1-based index，仅供显示 / 诊断
  name: string;
  category: string;
  description?: string;
  groupName?: string | null;
  assetRef: string;                  // 项目包内相对资源路径或受控资源键
  sourceRect: Rect;                  // source-image 像素坐标
  shape: SpriteShape;
  points?: Point[];                  // spriteLocal；rectangle 可省略
  contentVersion: number;            // 像素 / Alpha / mask / 几何缓存版本
  revision: number;                  // 本实体业务数据版本
  legacyAnchor?: Point;              // 原样保留的 V9 source-image 全局坐标
  legacyExtensions?: Record<string, unknown>;
}

interface SceneTransform {
  x: number;
  y: number;
  scaleX: number;
  scaleY: number;
  rotation: number;                  // 角度单位固定为 degree
}

interface SpriteRelations {
  nearTo: UUID[];
  attachedTo: UUID[];
  supports: UUID[];
}

interface SceneLayout {
  spriteId: UUID;                    // 与 SpriteAsset.id 对应
  layer: SpriteLayer;
  depth: number;
  parallax: number;
  zIndex: number;
  visible: boolean;
  locked: boolean;
  transform: SceneTransform;
  sceneAnchor: Point;                // sceneWorld
  relations: SpriteRelations;        // 所有引用均为 V10 UUID
  revision: number;
}

interface SceneLayoutDocument {
  items: Record<UUID, SceneLayout>;  // key 必须等于 item.spriteId
}

interface ProjectSettings {
  colorSpace: "srgb";
  pixelArt: {
    enabled: boolean;
    renderSnap: "round" | "floor" | "none";
  };
  defaultFps: number;
  autosaveEnabled: boolean;
  extensions?: Record<string, unknown>;
}

interface LegacyIdMapping {
  legacyId: string;
  spriteId: UUID;
  legacyIndex?: number;
  sourceFile?: string;
  status: "mapped" | "missing_asset" | "ambiguous";
}

interface MigrationMetadata {
  sourceFormat: string[];
  sourceProjectVersion?: number;
  migratedAt: string;
  adapterVersion: string;
  idMap: LegacyIdMapping[];
  warnings: MigrationWarning[];
}

interface MigrationWarning {
  code: string;
  severity: "info" | "warning" | "error";
  legacyId?: string;
  path?: string;
  message: string;
  resolution?: string;
}

interface ProjectDocument {
  kind: "sprite-project";
  projectSchemaVersion: 10;
  projectId: UUID;
  assets: SpriteAsset[];             // 唯一权威 Sprite 集合
  sceneLayout: SceneLayoutDocument;
  animationSets: AnimationSet[];
  animationClips: AnimationClip[];
  pivotPresets: PivotPreset[];
  projectSettings: ProjectSettings;
  migrationMetadata?: MigrationMetadata;
  legacyExtensions?: Record<string, unknown>;
  revision: number;                  // 项目级单调递增版本
}
```

规范与约束：
- `assets` 是唯一权威 Sprite 集合；任何 `sprites` 数组只能由 selector 从 `assets` 派生，禁止同时持久化两份可变集合。
- `sceneLayout.items` 必须为每个已布局 Sprite 提供至多一个条目；条目 key、`spriteId` 和对应 SpriteAsset.id 必须一致。未参与场景布局的 Sprite 可以没有条目。
- `SpriteAsset.revision`、`SceneLayout.revision`、`AnimationClip.revision`、`AnimationFrame.revision` 在各自实体的业务字段变化时递增；纯 UI 状态、播放时钟和缓存命中不递增。ProjectDocument.revision 在任一持久化业务事务成功提交时递增。
- `contentVersion` 仅在像素内容、Alpha / mask 或裁切几何变化并影响派生缓存时递增；名称、分类、场景变换和 UI 操作不递增。
- `sourceRect` 使用原始输入图像像素坐标；`points` 使用 spriteLocal 像素坐标。迁移器必须先识别 V9 points 的实际坐标基准，再归一化；无法确认时将原始值放入 `legacyExtensions.rawGeometry` 并警告，不得直接猜测。
- `sceneAnchor` 使用 sceneWorld；`legacyAnchor` 原样保存旧值及其 source-image 坐标语义，不能直接当作 sceneAnchor。
- `SceneTransform.rotation` 单位为角度；缩放无单位，平移 x/y 使用 sceneWorld 像素单位。
- V9 layer 枚举映射为 background / midground / foreground。缺失值才使用默认值：background depth=0.85、midground depth=0.5、foreground depth=0.15；parallax 默认分别为 0.35 / 0.70 / 1.00。已有数值必须原样保留。
- `relations` 的每个数组元素必须先经 legacy ID 映射转换成 UUID；目标缺失时不得留下悬空 UUID，应记录 unresolved relation warning 并把原始关系保存在扩展数据中。
- `legacyExtensions` 用于保留 V10 尚未建模的旧字段和来源数据，不得用它替代本节已定义的正式字段。

### 6.2 Project Settings 与 Migration Metadata

`projectSettings` 保存项目级用户偏好和默认值，不存放当前选中项、面板开合、播放时钟等临时 UI 状态。未知设置放入 `extensions`，不得静默删除。

`migrationMetadata` 是迁移审计信息，不是业务身份的替代品。其 `idMap` 必须完整记录每个 V9 sprite id 到 V10 UUID 的映射；生成 UUID 后先完成全量映射，再转换 relations、Agent 结果和其他外键。映射状态为 missing_asset / ambiguous 的记录不得被当作成功迁移。

### 6.3 坐标空间术语表


| 术语 | 定义 |
|---|---|
| sourceRect | 原始输入图像中的裁切矩形 |
| spriteLocal | 单个裁切 Sprite 局部像素坐标，左上角为 (0,0) |
| clipCanvas | Animation Clip 规范画布坐标，左上角为 (0,0) |
| sceneWorld | 场景布局世界坐标 |
| viewport | 编辑器屏幕视口坐标，包含视口缩放和平移 |
| sceneAnchor | 只服务场景摆放的锚点 |
| animationPivot | 只服务动画帧对齐的枢轴 |

禁止在跨模块接口中使用含义不明的泛化 canvas / world 字段名。若字段指动画画布，必须写 clipCanvas；若指编辑器视口，必须写 viewport。

Scene Anchor 与 Animation Pivot 是不同领域概念，不共享字段。详细动画坐标定义见《02-Animation-System-技术规格》。

## 7. 状态与修改原则

1. Reactive Store 是 Project 数据与 UI 可观察状态的权威来源。
2. Interaction Manager 是真实运行时 Gesture / Pointer Session 的唯一所有者。
3. Store 中的 InteractionSnapshot 仅为只读、可观察的 UI 快照（例如 gestureType、isInteracting；activeTool 唯一存储于 UIState.activeToolByWorkspace）；不得包含可被 UI 用来驱动真实指针会话的 pointerId、活跃 stroke buffer 或可变 draft。
4. UI 组件不持有第二份可独立修改的业务数据副本。
5. 业务数据只能通过 Command 修改。
6. 所有进入 History 的 Command 必须实现 undo；不可撤销的内部维护动作不得作为普通项目数据 Command 进入 History。
7. 批量操作使用 CompositeCommand / TransactionCommand，作为单一原子历史项。
8. 连续拖动在 pointerup 时提交为一个事务；pointercancel 时丢弃 draft 并回滚到开始前状态。
9. 派生数据通过 selector 计算，避免重复保存可推导字段。
10. Canvas 与面板从同一状态快照渲染。

### 7.1 动画播放与交互状态

PlaybackState 是 Animation System 的独立状态维度：Stopped、Playing、Paused；它不是 InteractionState 的一种 Gesture。Interaction Manager 同一时刻仍只允许一个主指针 Gesture。

当播放过程中开始拖动 Pivot 或 Frame Offset：
- 默认在 Gesture 开始时自动暂停播放，并记录暂停前状态。
- pointerup 提交校准后，默认恢复此前 Playing 状态；若用户设置为“操作后保持暂停”，则保持 Paused。
- pointercancel / lostpointercapture / blur 时先安全取消 Gesture，再按同一恢复策略处理播放状态。
- 切换 Clip、工作区或页面失焦时按 Animation System 规则清理播放时钟。
- PlaybackState 不进入 InteractionSnapshot 的互斥状态机，也不写入项目文件。

## 8. 渐进迁移路线

### Phase 0：基线固化
- 保存 V9 原始版本与可回退副本。
- 建立代表性项目样本和回归素材。
- 记录当前算法输出与关键交互行为。
- 为已知问题建立可复现步骤。

交付：V9 Baseline、测试素材包、已知问题清单。

## 9. 项目文件、V9 迁移与版本协议

### 9.1 V10 项目文件

V10 项目文件根必须同时包含类型判别字段与 schema 版本：
```json
{
  "kind": "sprite-project",
  "projectSchemaVersion": 10
}
```
`kind` 用于在解析前识别文件类型；`projectSchemaVersion` 是项目持久化 schema 的整数版本。二者均不能用来判断动画、场景或 Agent 导出协议。缺少 kind、kind 不匹配或 schema 不受支持时，打开器应停止项目导入并给出明确错误，不得通过字段嗅探将其他 JSON 当作项目文件。

### 9.2 V9 可迁移输入范围
V9 没有完整项目保存文件。兼容层只承诺读取以下实际产物：
- 场景导出 ZIP：sprites/NNN_名称.png + manifest.json。
- 单独导出的场景 Manifest（format: spatial-scene-layout/v2）。
- 可选的 Agent 任务 / 结果 JSON：spatial-scene-agent-task/v2、spatial-scene-agent-result/v2，以及已明确支持的旧 sprite-agent-result/v1。

这些输入不等同于完整 V9 工程快照。V9 内存中的 mask 没有持久化格式，无法从上述导出物恢复。不得在迁移验收中承诺 mask 无损迁移。

### 9.3 V9 → V10 字段映射表

| V9 字段 | V10 目标字段 | 转换 / 保留规则 |
|---|---|---|
| `id`（如 sprite_001） | `SpriteAsset.id` + `legacyId` + `migrationMetadata.idMap` | 为每项生成 UUID；旧 ID 永久保留为兼容键 |
| `index` | `legacyIndex` | 仅保留诊断序号，不作为身份 |
| `name` / `category` / `description` | 同名 SpriteAsset 字段 | 原样保留 |
| `group` | `groupName` | 保留字符串或 null |
| `visible` / `locked` | SceneLayout 同名字段 | 缺失时分别默认 true / false |
| `sourceRect{x,y,width,height}` | `SpriteAsset.sourceRect` | 原始输入图像像素，不做缩放 |
| `anchor{x,y}` | `SpriteAsset.legacyAnchor`、`SceneLayout.sceneAnchor` | 原样保存旧值；按 9.4 换算 sceneWorld |
| `layout.layer` | `SceneLayout.layer` | background / midground / foreground 枚举映射 |
| `layout.depth` | `SceneLayout.depth` | 已存在值原样保留；仅缺失时用层级默认值 |
| `layout.parallax` | `SceneLayout.parallax` | 已存在值原样保留；仅缺失时用层级默认值 |
| `layout.zIndex` | `SceneLayout.zIndex` | 原样保留；缺失时按原始顺序生成稳定值 |
| `transform{x,y,scaleX,scaleY,rotation}` | `SceneLayout.transform` | 原样保留；rotation 单位按 V9 实际定义转换为 degree |
| `relations.nearTo / attachedTo / supports` | `SceneLayout.relations` | 所有 sprite_id 先通过全量 idMap 转为 UUID |
| `shape` / `points` | `SpriteAsset.shape / points` | shape 枚举归一；points 转为 spriteLocal。旧坐标基准无法确认时保留 rawGeometry 并警告 |
| `file` | `SpriteAsset.assetRef` | 记录 ZIP 内安全相对路径，不接受路径穿越 |
| 未识别字段 | 对应实体或 Project 的 `legacyExtensions` | 保留原始键和值，并在迁移报告中列出 |

### 9.4 身份桥接、Anchor 换算与兼容边界

**Ordinal → UUID 桥接顺序：**
1. 读取所有有效 Manifest sprite 记录，收集 V9 `id`、`index` 和 `file`。
2. 为每个可导入素材生成 UUID，并一次性构建完整 `migrationMetadata.idMap`。
3. 再转换 relations、Agent 结果 JSON 及其他引用；禁止在映射表尚未完整时按数组位置临时推断。
4. Agent 结果中的 `sprite_id`、旧关系字段 `near_to` / `attached_to` 等别名只在 V9 Adapter 边界识别，进入 V10 领域模型前统一为 camelCase 与 UUID。
5. 无法解析的旧 ID 必须进入 warning / unresolved 列表，禁止按 index 猜测替代。

**V9 Scene Anchor 换算：**

V9 的 `anchor` 是 source-image 全局像素坐标；V9 场景平移语义为 `scenePosition = sourcePosition + transform.translation`。因此迁移公式固定为：
```ts
sceneAnchor = {
  x: legacyAnchor.x + transform.x,
  y: legacyAnchor.y + transform.y
};
```
只应用平移，不额外应用 scaleX / scaleY / rotation，避免重复变换。迁移验收必须选取至少 3 个具有不同平移量、缩放或旋转的 Sprite，对比 V9 与 V10 场景中的锚点世界位置；若实际 V9 渲染路径的语义核验发现差异，必须先修订本规则与测试，不得静默改变公式。

**V9 兼容协议冻结：**
- `spatial-scene-layout/v2` 的既有字段名、嵌套结构、枚举、序号语义和目录布局均视为冻结协议。
- V9 兼容导出不得为了遵循 V10 camelCase 而重命名旧字段；V10 camelCase 只约束内部模型和新协议。
- 兼容导出不得强制增加旧消费者不认识的字段。V10 UUID 与旧 ordinal 的关联通过独立 `sprite-id-map.json` 辅助文件提供；旧 Manifest 本体保持原样。
- 新动画 Manifest 的 Frame 记录可选携带 `legacySpriteId`，供旧场景 Manifest 与 V10 UUID 对照；没有 legacy ID 的新素材省略该字段。

### 9.5 Agent v1 / v2 适配协议

V9 Agent Adapter 至少识别已发布 V9 实际接受的任务 / 结果协议：
- `spatial-scene-agent-task/v2`
- `spatial-scene-agent-result/v2`
- `sprite-agent-result/v1`

V9 结果输入可能使用 `sprite_id`，关系别名可能使用 `near_to` / `attached_to`。这些旧命名仅在适配层接受；进入 V10 内部模型后统一为 `spriteId` 与 `relations.nearTo / attachedTo / supports`。不得把 V9 JSON 原样直接 cast 为 V10 类型。不同协议版本的字段差异必须由各自 adapter 显式校验；未识别字段保留到 legacyExtensions 并报告。适配器不得臆造缺失关系或素材身份。

### 9.6 迁移规则与异常输入处理
1. 迁移前保留原始导出物；迁移过程纯函数化，输出 ProjectDocument 与结构化 warnings。
2. UUID 在同一项目内唯一；生成并持久化后，后续保存 / 重开不得重新生成。
3. 旧 anchor 不自动推断为 Animation Pivot；旧 anchor 按 9.4 转换为 sceneAnchor，同时保留 legacyAnchor 来源值。
4. 未知字段放入 legacyExtensions，不能静默删除。
5. Manifest 缺失、JSON 无法解析、schema 不支持或 ZIP 损坏：阻断自动迁移并说明原因。
6. Manifest 引用的 PNG 缺失、不可解码或为 0 字节：跳过对应 Sprite，记录 error warning；所有引用它的 relations / Agent 标注标记为 unresolved，不生成悬空 UUID。
7. ZIP 中存在未被 Manifest 引用的有效 PNG：作为未分配素材导入（不自动猜名称、分类或场景位置），标记 orphan 并要求用户确认归属。
8. Manifest 文件路径与 ZIP 实际路径不符：以经过路径安全校验的 Manifest file 字段为准；找不到时不按相似文件名猜测，记录缺失资源。
9. 同一资源路径被多个 Sprite 记录引用：允许共享像素资源，但每个 Sprite 保留独立 UUID；若同一旧 ID 重复出现或路径存在歧义，则相关记录标记 ambiguous 并要求用户处理。
10. 拒绝绝对路径、`..` 路径穿越和重复规范化路径；不得从 ZIP 外部读取文件。
11. 迁移报告列出成功、跳过、警告、无法自动映射项目和不可恢复数据；用户确认后另存为 V10 项目，不覆盖原始文件。
12. V9 导出物未包含的 mask 不参与迁移；需要 mask 时必须重新切割或精修。

### 9.7 导出协议并存
- V9 兼容场景导出保留冻结协议：format = spatial-scene-layout/v2，字段名、目录与序号语义不变。
- V10 动画导出使用独立 format = sprite-anim-manifest/v1，内部字段使用 camelCase。
- V10 项目文件使用 kind = sprite-project 与 projectSchemaVersion = 10。
- 两种导出在 UI 入口、文件命名和 Manifest 解析器中明确区分，不互相覆盖。
- `sprite-id-map.json` 在需要跨接 V9 场景与 V10 动画数据的导出包中提供 legacyId ↔ spriteId 映射，不修改冻结的 V9 Manifest。
- 项目版本、导出 format 与 Agent 协议版本互不替代。

## 11. Agent 实施约束

Agent 每个阶段必须：
1. 先阅读本目录三份规格和 V9 基线文件。
2. 明确本阶段允许修改的模块和禁止修改的算法。
3. 先给出实施计划和受影响文件清单。
4. 小步提交，不在一个任务中同时重写多个核心系统。
5. 为每个新增行为提供自动化测试或可复现手工验收步骤。
6. 不得为了通过测试而删除旧功能。
7. 每阶段结束提供变更摘要、测试结果、已知限制和回滚方式。
8. 未经明确授权，不得直接把实验性版本替换为正式 V9 文件。
9. 严格遵守三份规格的坐标术语、状态归属、命令事务与导出协议。

## 12. V10 阶段完成定义

V10 不是以「界面看起来完整」作为完成标准。至少满足：
- V9 实际导出物可迁移，且不可恢复数据明确告知。
- 原有图像算法回归通过。
- 交互状态不冲突，指针异常能恢复。
- Interaction Manager 独占真实 Gesture 会话。
- 多面板由统一 Store 同步。
- 数据修改有一致的撤销 / 重做和原子事务。
- 动画数据能保存和重开。
- 组级 / 单帧校准能互相配合。
- 自动校准不覆盖手工结果。
- 预览和导出位置一致。
- PNG 序列、JSON、Sprite Sheet 的坐标与 Trim 结果可验证。
- 核心编辑流程离线可用；联网依赖能力有明确标识。
